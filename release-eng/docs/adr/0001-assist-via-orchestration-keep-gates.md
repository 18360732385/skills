# 辅助发版靠编排，硬闸保留并加评审草稿

release-eng 下一阶段（朝 0.4）的产品取舍：北极星是半自动编排与可恢复闸状态，而不是削弱 push-gate / 确认词 / 逾期 seal。协作「先审再推」用一等公民评审草稿通道解决；消费仓保留仓内脚本快照，并加版本对齐闸，避免全局 skill 与快照行为分叉。

**Status**: accepted（落地细节部分由 [0002](0002-identity-by-date-no-draft-store.md) 修正：无草稿落点、无闸状态续跑；版本身份改跟发版日期）

**Considered Options**:
- 软化硬闸以换协作速度 → 拒绝（RED 压测显示无闸时借口绕过率高）
- 取消仓内快照、只跑用户级 skill → 拒绝（实仓 CI/离线仍需可跑副本）
- 优先拆 freeze 巨石 / 只追采集可靠性 → 延后为主叙事（继续实仓回流，但不替代编排）

**Consequences**:
- `release.mjs` 需从「只打印指引」演进到可 `--until` / 恢复闸状态的编排入口
- 须定义评审草稿的物理位置与逾期扫描排除规则
- 仓内 `scripts/release-eng/` 需要可检测的版本对账
