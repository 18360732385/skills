1. 这个技能是做什么的？

release-eng 把「发版」做成一份可交付、可审计、可归档的发版单：读 Git 的实际改动（分支对、提交、合并来源），把 SQL / 配置 / 定时任务三类上线物挑出来，配上说明，落成目录包，上线后归档。

做不做
采集这次的改动范围（freeze）不决定业务要不要上（那是你的事）
生成并维护发版单 + 目录包（note-merge）不执行上线（不跑 SQL、不改生产配置）
校验 push 状态、归档状态（push-gate / seal-check）不替代 CI、不替代代码评审

须点名加载。技能带 disable-model-invocation: true——它会写 docs/releases/、会卡硬闸，不该在你没打算发版时冒出来。

1.1 四个模式

模式什么时候用一句话
prepare新建一份发版单首问 → push-gate → freeze → 问卷 → WritePlan
resume同一版本身份接着干刷新自动段 / 补问卷 / 再定版
audit只想体检，不想动文件只读看 prior·freeze·缺章，永不写盘
seal已经上线了seal-check 通过后 进行中目录 → archive/

未指定时怎么判：说「继续 / 刷新」→ resume；「检查 / 审计 / 看看」→ audit；「上线了 / 归档」→ seal；其余（「准备发版单」「下个版」）→ prepare。

1.2 三条硬规则

RULE 01

首问齐才进 push-gate

发版日期 + 发版分支 +（基线或 首次发版）三项确认过才往下走。领导口述也要回显一遍。

RULE 02

确认词才写盘

docs/releases/** 只在词表内确认（或同会话预授权）后写。audit 永不写盘。

RULE 03

非 harness land

不对齐工程化自动流水线；跨仓靠整目录拷贝 + 点名仪式。

1.3 解决什么问题

  1. 发版靠人肉记忆：谁改了什么、配置动没动、SQL 跑了哪几条，全在几个人脑子里。
  2. 上线清单散在 commit 里：上线前才开始翻 git log，边翻边漏。
  3. 配置和 SQL 靠翻代码：prod 改了哪个键、哪条 migration 是本版的，得一个个开文件看。
  4. 归档无从追溯：半年前那版什么时候上的、谁上的、清单是什么，查不到。

一句话：把「这次上线」变成一份带 Git 证据的清单，落盘、可审、可归档。

1.4 什么时候不要用它

你的诉求别启动本仪式
只想知道 changelog / commit message 怎么写不需要发版单目录包，直接问就行
普通代码评审走代码评审，不是发版归档
归档的不是 docs/releases/ 下的东西本技能的硬闸只管发版目录包
只想看分支差多少audit 够用，但纯 git log 更快

2. 安装、前置与骨架 bootstrap

2.1 安装

装在当前宿主的用户级 skills 目录。release-eng 是整目录可移植的：modes/、scripts/、fixtures/ 缺一不可（脚本会读 fixtures/ 当骨架种子）。

帮我把这个 skill 装到你当前 Agent 宿主的用户 skills 目录，地址：
https://github.com/18360732385/skills/tree/main/release-eng
必须整目录（含 fixtures/、scripts/、modes/），保证目录内直接有 SKILL.md，装完告诉我实际路径。
npx skills add https://github.com/18360732385/skills/tree/main/release-eng -g

装好后新开一轮会话，再显式点名 release-eng。

2.2 命令前缀（先看这一段）

技能文档里的命令统一写 .cursor/skills/release-eng/scripts/。本手册为了能直接照抄，统一写 release-eng/scripts/。实际替换：

你的安装位置把 release-eng/scripts/ 换成
本仓（skills/ 下自测）原样可用（在仓根跑），或 cd release-eng 后用 scripts/
Cursor 项目级.cursor/skills/release-eng/scripts/
用户级 / .agents/skills/<host-skills>/release-eng/scripts/（绝对路径最稳）

下文命令都按「在目标业务仓根执行、技能装在 release-eng/」书写。换位置时只替换前缀，参数不动。

2.3 前置条件

  • Node.js（脚本全是 .mjs，无第三方依赖）。
  • 目标仓有 origin 远端，且发版分支已 push（push-gate 的核心检查）。
  • docs/releases/ 要么已存在，要么让 bootstrap 从 fixtures 建。

2.4 骨架 bootstrap

prepare / resume / seal 开头都会检查这四个路径，audit 默认只报告缺失、不创建：

路径作用
docs/releases/releases.md进行中索引（导航 + 状态）
docs/releases/templates/release-note-template.md发版单模板（11 章）
docs/releases/archive/已上线归档目录
docs/releases/ARCHIVE.md已上线索引（按日期倒序）

来源优先级：已有 → skip（保留你的正文）；缺失 → 从 fixtures/docs/releases/ 复制。骨架创建本身不经 WritePlan，完成后打印 bootstrap: 已创建 … 或 bootstrap: 已齐全，跳过。

docs/releases/notes/ 是旧路径：0.3.27 起不再新建，脚本仍兼容读（计划 0.4 移除）。老仓建议先迁到 docs/releases/<slug>/。

2.5 可选的 repo-profile

目标仓可放 docs/releases/repo-profile.json 覆盖内置默认：

branchSlugCn（分支名→中文功能映射）· syncTaskCodeFallbackPaths · knownServices · configCatalogFiles · thirdPartyKeywords · moduleBlurbs · artifactKeyPrefixes

与内置默认深合并（profile 优先）；文件缺失或 JSON 非法时回退内置默认，不会中断发版。

3. 一次发版怎么走（主流程）

3.1 日常话术表

你说触发结果
「准备发版单」/「下个版」prepare首问 + push-gate + freeze + 问卷 + WritePlan
「继续上次的发版单」/「刷新一下」resume同版本身份续跑，刷新自动段
「审计一下」/「体检」audit只读报告，不写盘
「已经上线了」/「归档」sealseal-check → 整夹移入 archive/
「全部推荐」问卷 / 首问采用本轮所有【推荐】预填（不等于写盘许可）
「确认」/「按计划执行」/「LGTM」WritePlan 闸门才开始写盘
「确认预授权」WritePlan 闸门本轮确认 + 同会话后续同 slug 自动写盘

3.2 首问三项（第一道闸）

项【推荐】说明
发版日期≥ 提问日 + 2 天的第一个周四独立元信息字段，不拼进目录名
发版分支release可预填上次值或索引里的值
基线分支main填 无 即 首次发版

发版日期算法（提问日为基准）：

提问日提问日 + 2推荐周四
周二 Aug 18Thu Aug 20Aug 20（本周四）
周三 Aug 19Fri Aug 21Aug 27
周四 Aug 20Sat Aug 22Aug 27
周五 Aug 21Sun Aug 23Aug 27
权威口述 ≠ 跳过首问
领导说「别问了，release 对 main，日期写周四」，仍要把三项回显请他确认（或走 全部推荐 展示预填），然后才进 push-gate。禁止未回显就写 docs/releases/<slug>/。

版本身份 <slug> = 发版分支名归一化（去 origin/、refs/heads/、refs/remotes/ 前缀，/ → -，连续 - 收敛）：origin/release/V260827 → release-V260827。所以路径是 docs/releases/release-V260827/release-V260827.md。改发版日期不影响路径，只改元信息日期字段。

3.3 push-gate（第二道闸）

# 增量发版（有基线）
node release-eng/scripts/release.mjs push-gate -- --root . --release release --baseline main

# 首次发版（基线=无）
node release-eng/scripts/release.mjs push-gate -- --root . --release release --baseline none
分支对通过条件
发版 + 基线两侧都要有 origin/<name>，且相对 origin 未推送 = 0
发版 + 首次发版仅发版分支要有 origin/<发版>，未推送 = 0；baseRef=null

Exit：0=通过 · 2=未通过 · 1=执行错误（fetch 失败等）。通过后把 baseRef / headRef（首次发版用 hints.freezeArgs）交给 freeze。

中止时不许「落盘给评审」
「先把发版单落盘，push 我稍后」「别堵着大家」都不改变结论。草稿可以贴聊天或 gist，但不要写 docs/releases/<slug>/**、不要写 artifacts.json、不要出可执行的定版 WritePlan。unpushed 不是「只挡上线、不挡写盘」。

--no-fetch 只给排障 / 只读检查（audit、离线）用；默认会 git fetch --prune。

3.4 freeze（定版采集）

# 增量：路径 + yml/Java 键级·任务级 diff，双源去重
node release-eng/scripts/release.mjs freeze -- --root . --base origin/main --head origin/release --format json

# 首次发版：Git 全量 + 分层候选（非空 draft）
node release-eng/scripts/release.mjs freeze -- --root . --first-release --head origin/release --format json

# 一屏摘要（白话摘要主输入）
node release-eng/scripts/release.mjs freeze -- --root . --base origin/main --head origin/release --format summary

# 写盘预填预览（三章表；WritePlan 必贴）
node release-eng/scripts/release.mjs freeze -- --root . --base origin/main --head origin/release --format draft-md

Windows / PowerShell 务必用 --out <file> 落盘，别用 > file——后者会写成 UTF-16 LE BOM，后续 JSON.parse 直接失败。

产物（按重要度）：Git 二表、releaseSummaryLines、candidates / changeObjects、draft / draftSuppressed、priorRelease、confidence、mergeSources、aiTrack（stub）、inventory（首次）、jobsConfigGaps、indexDrift、overdueNotes。

置信度四级（问卷展示时必须带）：

级别含义
docs-hit已挂上 docs/jobs 真相或 SyncTaskCode
catalog-hit配置说明命中 README / AGENTS 表
key-diffyml / Java 键级或注解 diff
path仅路径启发式（建议人工确认）

prior 三档：--prior auto（默认，archive 全量并集，优先读 artifacts.json）、--prior none（关闭清单侧）、--prior-since <日期|身份>（只并入该前缀之后的归档）。命中「线上已存在」的项进 draftSuppressed，不写进正文——但配置/任务的键值变更例外：键在基线里有、本版改了值，仍进 draft（标 priorKeyHit，值列展示 旧→新）。

3.5 AI 轨（双轨研判，可选）

node release-eng/scripts/release.mjs ai-track -- --root . --freeze-json /tmp/freeze.json --format prompt-md
node release-eng/scripts/release.mjs ai-track -- --root . --freeze-json /tmp/freeze.json --ai-json /tmp/ai-track.json --format json --out /tmp/freeze-with-ai.json
  • 规则轨不得因 AI 静默消失——aiNoise 只是「问卷默认不勾选」，不是从 draft 删除。
  • stableId 必须来自 prompt 列表，不在候选集的会被拒绝并记入 aiTrack.rejectedUnknown。
  • AI 失败 / 超时 → 跳过，纯规则继续（规则轨就是漏检底线）。

3.6 问卷

每批 ≤ 5 题，每题给【推荐】，可回 全部推荐。

类型题目
固定三题版本身份 slug（= 分支名归一化）、上线内容摘要（1～5 项业务短句）、发版负责人
自适应六题数据库与 SQL、配置项、定时任务、第三方与外部依赖、上线步骤与回滚、风险与验收（有候选或首次 inventory 才深问，否则该章记「无」）

目标 profile 一律 prod。规则：priorOnly 与 path 级低置信项必须标「建议人工确认」，不得和 docs-hit 同级展示；aiNoise 命中项默认不勾（可拉回）；首次发版时 inventory.migrationRange 要单独确认起迁版本，别把 layerSuppressed 当已确认上线清单。

3.7 WritePlan 与确认闸门（第三道闸）

展示顺序强制五段：

  1. 白话摘要：模式 / 发版日期 / 分支对 / 版本身份 / Git 表口径 / 目录包 / 目标 profile / draft 计数 / 密文键名 / push-gate 状态
  2. 技术摘要：目标根 / on_exists / 发版单路径 / 索引 / 预授权 / freeze 来源
  3. 路径动作表：create / merge / refresh 逐行
  4. draft 预览（三章表）：把 --format draft-md 的 stdout 原样贴上
  5. Git 定版摘要：截断后的提交 / 合并来源要点 + 远端浏览链接

写盘当且仅当你回复下列任一：确认 · 确认写入 · 按计划执行 · 执行 WritePlan · LGTM

不算确认（须再问一句）：看着不错 · 继续吧 · 继续 · 好的 · 可以 · 👍 · Slack reaction ·「按你说的办」而未含上列词。

回复 确认预授权 后：本轮仍要完整确认一次；同会话后续 resume / 同 slug 刷新自动写盘；说「取消预授权」恢复逐轮确认。

3.8 note-merge（落盘）

node release-eng/scripts/release.mjs note-merge -- --root . \
  --note docs/releases/<slug>/<slug>.md \
  --freeze-json /tmp/freeze-with-ai.json \
  --baseline main --identity <slug> \
  --release-date 2026-11-19 --release-branch release --owner <负责人>

它做四件事：写发版单自动段、生成 artifacts.json、把本版新增原件拷进 sql/refs/ config/ jobs/、按需生成 sql/release-V{yyMMdd}-DDL|DML.sql，并默认回写 releases.md（--no-update-index 可关）。--dry-run 只看「将写多少字节、draft/bundle 各几行」。

警示
note-merge 刷新会先清空包内 sql/ / config/ / jobs/ 三个目录再重建（内容来自 draft）。手工放进这三个目录的文件会被清掉——别往里存手工产物。

分类归不闭环时脚本会在 stderr 打 classify prompt，Agent 自动补 --sql-ai-json 续跑，不会来问你。

4. 四个模式详解

4.1 prepare（主路径）

步骤：gates-common（bootstrap + 逾期预检 + 首问）→ git-gates（push-gate）→ freeze → ai-track（可选）→ 定身份 → questions → write-plan（draft-md 预览 + 确认）→ note-merge。

Done 要点：发版单存在且 Git 二表完整（截断5 + mergeSources）；元信息有 1～5 项上线内容摘要和已确认的发版日期；目录包含 sql/refs/ config/ jobs/README.md artifacts.json；releases.md 有对应行；draftSuppressed 没被误写进正文。

4.2 resume（同版本身份续跑）

  • 发版日期沿用既有值（别擅自改成「新的推荐周四」）。
  • 定位发版单：给 slug，或进行中只有一行，或多行要你选。
  • on_exists 默认 merge：刷新自动段、保留人工段、刷新包内附属拷贝。
  • <!-- manual:start --> … <!-- manual:end --> 内的正文不会被覆盖（你没要求覆盖时）。

4.3 audit（只读体检）

只出报告，写盘动作为「无」。报告七个强制二级标题：

## 骨架 · ## 进行中 · ## push-gate · ## prior · ## freeze · ## 缺章 · ## 密文键

每节必须给实质内容或显式「无 / 未检查 / 未跑」。用 freeze --format audit-json 填 prior / freeze 两节；离线或不想更新远端引用时给 push-gate 加 --no-fetch。密文节只列键名，不展开值。

4.4 seal（已上线归档）

前置：状态为 已定版（或你书面要求「强制 seal」并记入变更说明）；已拿到实际上线日期与执行人。

# 先体检
node release-eng/scripts/release.mjs seal-check -- --root . --note docs/releases/<slug>/<slug>.md

# 看计划（默认 dry-run）
node release-eng/scripts/release.mjs seal -- --root . --note docs/releases/<slug>/<slug>.md \
  --online-date 2026-11-19 --executor 张三 --dry-run

# 确认词之后写盘
node release-eng/scripts/release.mjs seal -- --root . --note docs/releases/<slug>/<slug>.md \
  --online-date 2026-11-19 --executor 张三 --apply

seal-check 有 error 就中止（除非你明示强制并加 --force）；warning 可继续，但要在 WritePlan 白话摘要里列出。检查项包括：artifacts.json 与 md 的 SQL 主键是否对齐、sql/refs/ 存在时是否带 sqlBundles 且与整理文件哈希一致、密文（不因密文失败）。

--apply 一次做四件事：状态 → 已上线、填上线日期 / 执行人、整夹 mv 到 archive/<identity>/、进行中表删行 + ARCHIVE.md 追加。脚本不可用时按同样四步手工做。

5. 约定 SSOT（九条）

唯一权威在 modes/conventions.md。其它文档只引用不复述；本节做摘要，冲突时以 conventions 为准。

#约定要点
①发版日期算法第一个满足 日期 ≥ 提问日 + 2 天 的周四；独立字段，不进目录名
②版本身份与目录包slug = 分支名归一化；docs/releases/<slug>/ 六件套，无 notes/ 中间层
③Git 定版展示截断5、hash 前 8 位、mergeSources 去重全量、来源分支功能 ≤28 字、Asia/Shanghai
④目标 profileSQL / 配置 / 任务一律 prod；配置只收 application-prod.yml + nacos prod overlay
⑤SQL 序与整理版本号数字升序；*_change.sql 仅对照；DDL/DML 双轨、缺侧不落盘；先 DDL 后 DML
⑥密文策略配置章与 artifacts.json 允许密文；索引与白话摘要只列键名
⑦notes/ 兼容旧路径只读兼容，0.3.27 起不再新建
⑧repo-profile见 §2.5，深合并、缺失回退
⑨逾期书面跳过只有书面说明 + --overdue-waived "<说明>" 才放行；口头豁免无效

7. 硬闸、红旗与机检

7.1 五道硬闸

闸时机不过会怎样
首问每次 prepare / resume 入口不进 push-gate；三项没回显确认就不许写目录包
逾期未归档gates-common 预检 + freeze 再拦一次已定版 且发版日期已过 → 硬闸中止（先 seal）；准备中 → 软提醒
push-gate首问之后未推送 ≠ 0 → 模式中止，不得落盘
WritePlan 确认词任何写盘前非词表口语 → 再问一句；audit 永不写盘
骨架prepare / resume / seal 开头缺失从 fixtures 建；fixture 自身缺失就停下说明，别拿空文件冒充模板

7.2 Red Flags — 见到就停

  • 「别问日期/分支了，直接写」→ 仍回显首问三项并记确认，再 push-gate
  • 「旧单以后再 archive」→ 逾期已定版是硬闸，先 seal（或你书面跳过）
  • 「先落盘给评审，push 稍后」→ push-gate 未过就别写 docs/releases/<slug>/ 和 artifacts；聊天可以贴草稿
  • 「看着不错，继续吧」/ Slack 👍 → 不是确认词
  • 「archive 只是 housekeeping / 硬闸只管 optics」→ 假；逾期硬闸挡的是并发定版混乱

7.3 借口对照

借口现实
领导已口述参数 = 仪式关闭须回显确认记入首问；仍走 push-gate → WritePlan
已定版 archive 可以 TODO 后补日期已过且仍在进行中目录 → 先 seal，再新 prepare
unpushed 只挡执行、不挡落盘未通过 = 模式中止；评审用聊天 / gist
「继续」≈ 确认；卡词表没意义写盘只认词表；非正式口语一律再问一句
违反字面规则 = 违反精神
权威催促、窗口将至、草稿已赞、沉没成本都不构成例外。

7.4 逾期硬闸怎么放行

freeze JSON 里 overdueHardGate=true 时，note-merge 必须带书面说明：

node release-eng/scripts/release.mjs note-merge -- --root . --note docs/releases/<slug>/<slug>.md \
  --freeze-json /tmp/freeze.json --overdue-waived "11-20 大促后统一归档，已与发布经理确认"

跳过记录会写进 artifacts.json.overdueWaived{reason,date}。不传这个参数 → 直接拒绝写盘（exit 1）。

8.2 FAQ

Q1 点名了没反应？

确认技能在宿主可加载目录、新开过会话、并显式说了「release-eng」。它不点名不会加载。

Q2 首问能不能跳过？直接按 release 对 main 写？

不能。三项必须回显确认（或走 全部推荐 展示预填）。领导口述也一样。

Q3 push-gate 一直说未推送？

先 git push origin <分支>。缺 origin/<分支> 等于「从未推送」，不是「本地有就行」。基线侧同理。

Q4 能不能先落盘给评审，push 我稍后补？

不能。push-gate 未过 = 模式中止。草稿可以贴聊天或 gist。

Q5 发版日期和目录名是什么关系？

没关系。目录名是分支名归一化；发版日期只是元信息字段，改了也不动路径。

Q6 首次发版的基线怎么填？

填 无（脚本 --baseline none）。push-gate 只验发版分支；freeze 走 --first-release 分层候选；元信息基线写「无」。

Q7 逾期了怎么办？

先 seal 旧单，再 prepare 新的。真要先定新版，得给书面说明并让 note-merge 带 --overdue-waived，口头豁免无效。

Q8 note-merge 把我的手工文件清掉了？

它刷新时会先清空 sql/ config/ jobs/ 再按 draft 重建。这三个目录别放手工产物；手工内容放发版单正文的人工段。

Q9 配置里有密码会不会泄出去？

配置章和 artifacts.json 允许密文（这是设计），但 releases.md 和 WritePlan 的白话摘要只列键名不展开值。索引里别抄正文。

Q10 manual 段会被覆盖吗？

resume 默认不覆盖（除非你要求）。自动段刷新只动 <!-- auto:* --> 包起来的部分。

Q11 版本以谁为准？

_meta/manifest.yaml 的 version。CHANGELOG.md 是历史；docs/releases/releases.md 只引用不另钉号。0.3.x 是补丁序，别因为本轮改动跳 0.4.0。

Q12 只想体检，别动任何文件？

说「审计一下」走 audit。它只出报告，写盘动作为「无」。
