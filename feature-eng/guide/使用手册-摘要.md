# feature-eng 一分钟导读

> 版本：**0.2.28**（以 `_meta/manifest.yaml` 为准）

给业务同学 / 负责人的短文。完整版见 [使用手册.md](使用手册.md) · 浏览器版 [使用手册.html](使用手册.html)；Agent 入口见 [QUICKSTART.md](../QUICKSTART.md)。

## 它是什么

一套 **开发流程仪式**：把「一次功能开发」拆成 11 个环，每环有产物、有审核、有闸门，全过程落在目标仓 `docs/runs/` 里，可续跑、可复盘。

它是**调度员**，不是写代码的那个：自己只维护进度、勾形状检查、调审核、按绑定主动调起子 skill；真正写 ADR / Spec / Plan / 代码的是你绑定的「厨师」。

## 解决什么

- 流程只在人脑里：什么算「设计完了」「能开工了」，每次都要重吵
- 进度靠记性：换个会话就断片，Spec 写没写没人知道
- 审核走过场：「我审过了」没有落盘结论，无法追溯
- 收口漏项：Spec 还挂在「进行中」，归档没做，坑点没回流

## 怎么用

1. **装**：让 Agent 装到你当前宿主的**用户级** skills 目录（`https://github.com/18360732385/skills/tree/main/feature-eng`），或 `npx skills add <同上URL> -g`。装完**新开会话**，点名 **feature-eng**（它不会自动加载）。
2. **绑**：首次说「初始化绑定」，它会列出 11 环推荐表让你选（推荐包 / minimal / 逐环改），然后写 `docs/runs/stage-bindings.yaml`。
3. **开工**：说「开工」+ 需求。它会提议 **S / B / F** 一条路径（Spike 探查 / Bounded 小改 / Full 新子系统），你确认后建 `docs/runs/active/<slug>/`。
4. **推进**：每环干完说「环 N 完成」。它跑 L1（产物在不在）→ L2（审核语义）→ 需你确认的硬闸 → 写进度 → 自动拉下一环。
5. **收口**：说「收口」。双归档（runs + Spec/Plan）+ 契约同步 + 坑点三问，然后目录进 `archive/`。

日常还可以说：「继续」续跑、「看看进度」只读播报、「本环返工：…」退回重做、「暂停」写交接。

## 三条硬规则

1. **调度员不进厨房**——控制器不写领域正文、不写业务代码。
2. **进度只有控制器能写**——厨师结束后只回报「产物路径列表」。
3. **自动调起 ≠ 替你说 yes**——它可以主动拉下一个 skill，但硬闸仍要你亲口确认。

## 怎样算一环过了

两把尺子叠加：

| 层 | 查什么 | 谁做 |
|---|---|---|
| **L1 形状** | 该环产物在不在、字段非空、链接能打开 | 控制器 |
| **L2 语义** | 内容够不够撑起「可以离开这一环」 | 审核员，写 `审核-<stage>.md` |

写 `gates` 时间戳前必须三件齐：回链授权行合法、适用环审核文件 `result: pass`、代理模式下回链「仪式与降级」非空。机检 `node scripts/feature.mjs gate-evidence --cwd <仓根> --slug <slug>`。

## 别和工程化仓搞混

| 说法 | 真相 |
|---|---|
| 「顺手把仓工程化」 | 不做。需要工程化仓先做工程化，**新会话**再点名本 skill |
| 「`resume` 是补工程化缺口」 | 本 skill 的 `resume` 是**续跑主题** |
| 「计划 Go 闸过了就能让 AI 改业务」 | 那是仓库侧 `ai_coding_ready` 的事 |
| 「环间 L1/L2 = 阶梯 L1/L2」 | 两套词。这里 L1 是形状、L2 是语义 |

## 记住三句话

1. **调度员不进厨房**：控制器只管流程，产出归厨师。
2. **写 `gates` 前先有 `result: pass`**：没有审核文件就没有推进闸。
3. **没厨师也要显式降级，不许静默**：proxy 可以，悄悄戴帽不行。
