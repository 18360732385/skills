## 1. 这个技能是做什么的？

**feature-eng** 把「一次功能开发」做成可复盘的仪式：分诊 → 澄清 → 设计 → 规格 → 计划 → 实现 → 门禁 → 验证 → 收口，每一环有产物、有审核、有闸门，全过程落在目标仓的 `docs/runs/` 里。

它是一个**控制器（调度员）**，不是写代码的那个：

| 角色 | 是谁 | 干什么 |
|---|---|---|
| **控制器** | feature-eng 本体 | 分诊、维护进度、勾 L1、调度 L2、按绑定主动调起子 skill、过闸后进下一环、收口归档 |
| **厨师** | 你绑定的子 skill（澄清/设计/计划/实现…） | 写领域产物：ADR、Spec、Plan、原型、用例、代码 |
| **审核员** | L2 语义审核 | 只写 `审核-<stage>.md`，给 `result: pass / fail` |

**核心口诀：调度员不进厨房。** 详见 §1.2。

技能须**点名**加载（`disable-model-invocation: true`），不会被自动唤起——这是有意的：它会写文件、会卡闸门，不该在你没打算用它时冒出来。

### 1.1 主循环

```text
init（首次绑 11 环；可选推荐包 / minimal）
  → start（分诊 S/B/F · 建 docs/runs/active/<slug>/）
    → 子 skill 干活（lookup / 指针卡片）
      → advance（L1 → L2 → 写盘 → 按 handoff_policy 调下一环）
        → … 循环至收口
          → close（active → archive）
```

一次性动作：`init`（首次）、`rebind`（改映射）。日常动作：`start` / `resume` / `status` / `advance` / `close`。

### 1.2 三条硬规则

| # | 规则 | 意思 |
|---|---|---|
| 1 | **调度员不进厨房** | 控制器不写领域正文、不写业务代码。控制器兼代厨师只发生在 `chef_mode=controller_proxy` 的显式降级下 |
| 2 | **`progress.yaml` / `回链.md` 只有控制器能写** | 厨师结束后只「回报产物路径列表」，不许自己改进度 |
| 3 | **自动调起 ≠ 替用户 yes 硬闸** | 控制器可以主动把下一个 skill 拉起来，但硬闸仍要你亲口确认 |

### 1.3 写盘权责（SSOT）

| 谁 | 可写 | 不可写 |
|---|---|---|
| **控制器** | `progress.yaml`、`回链.md`、runs 模板骨架、`交接.md`、gates 时间戳、`artifacts.*` | 领域产物正文、业务代码、仓库根 `CONTEXT.md` |
| **子 skill（厨师）** | ADR / Spec / Plan / 原型 / `测试用例.md` / `术语增量.md` / 代码 | `progress.yaml`、`回链.md`、gates 时间戳、根 `CONTEXT.md` |
| **L2 审核** | 仅 `审核-<stage>.md` | `progress.yaml`、`回链.md`、领域正文、业务代码 |

硬轨：不得跳过硬闸或伪造勾选；未完成首问就写盘/改绑；厨师或审核员代写 progress / `回链.md`；替用户 yes 硬闸。

### 1.4 解决了什么问题

1. **流程只在人脑里**：什么算「设计做完了」、什么算「可以开始写代码」，每次都要重新吵一遍。
2. **进度靠记性**：换会话就断片，谁也不知道 Spec 写没写、Plan 审没审。
3. **审核走过场**：没有落盘的 `review` 结论，「我审过了」无法追溯。
4. **收口漏项**：Spec 留在「进行中」、归档没做、坑点没回流，下个人踩同一个坑。

一句话：**把开发流程做成有产物、有证据、可续跑的状态机**；具体用什么 skill 干活则是可换的——绑定表说了算。

### 1.5 与工程化仓（常见实现别名 `harness-eng`）的关系

本 skill **独立完整**：没有工程化 meta 也能 `init` / `start`。两者是**先后接力**，不是同一个东西。四组最容易搞混的点：

| 容易被误读成 | 实际是 |
|---|---|
| 「feature-eng 顺手把仓工程化」 | 不做。它不 land / fill / upgrade 工程化仓，也不改 `docs/harness-eng/`。仓需要工程化时，先完成工程化 → **新会话**再点名本 skill；**同会话勿并行**点名两者 |
| 「`resume` = 给工程化仓补缺口」 | 本 skill `resume` = **续跑主题**（`docs/runs/active`）。工程化仓续跑是另一件事 |
| 「计划 Go 闸过了 = 仓库可以开干了」 | 环 5 `gates.go` 只是「这份计划可以开工」；仓库能不能让 AI 改业务看的是工程化侧的 `ai_coding_ready` |
| 「环间 L1/L2 = 工程化阶梯 L1/L2」 | 完全是两套词。本手册的 L1 = 产物**形状**勾选，L2 = **语义**审核；工程化仓的 L1/L2 指契约骨架/知识回流 |

`start` 会做一次**只读软探测**（`eng_probe`）：发现工程化 meta 就在 `回链.md` 记一行 `ai_coding_ready`；**只提示，不阻断**，你没工程化也照跑。

## 2. 如何安装、init 与 rebind

### 2.1 安装

技能装在**当前 Agent 宿主的用户级 skills 目录**（保证 `SKILL.md` 在技能根目录）。**不要**装成项目级（例如 `.cursor/skills/`）再指望工程化 sync 托管——控制器与 sync 是解耦的。

对当前对话里的 Agent 说：

```text
帮我把这个 skill 装到你当前 Agent 宿主的用户 skills 目录，地址：
https://github.com/18360732385/skills/tree/main/feature-eng
保证目录内直接有 SKILL.md，装完告诉我实际路径。
```

或自己跑 CLI：

```bash
npx skills add https://github.com/18360732385/skills/tree/main/feature-eng -g
# 需要指定宿主时加：--agent <host>
```

手动拷贝（保证 `<host-skills-dir>/feature-eng/SKILL.md` 直接存在）：

```powershell
# Windows
Copy-Item -Recurse -Force <源>\feature-eng <host-skills-dir>\feature-eng
```

```bash
# macOS / Linux
cp -R <源>/feature-eng <host-skills-dir>/feature-eng
```

装好后**新开一轮会话**，再显式点名 **feature-eng**。

### 2.2 前置条件

- 本机可用 **Node.js**（`scripts/*.mjs` 全部是 `.mjs`，无第三方依赖）。
- 目标仓根目录可写（`docs/runs/` 会建在这里）。
- 要绑的子 skill 得能点名调起；装不了就走 `controller_proxy`（见 §7.1）。

### 2.3 init — 首次绑定 11 环

`init` 只干一件事：在**目标仓**写出 `docs/runs/stage-bindings.yaml`。

**绑定解析序（三档，所有模式共用）**

1. 目标仓 `docs/runs/stage-bindings.yaml` —— **运行时 SSOT**
2. 技能包 `config/stage-bindings.yaml` —— 回退种子（必须在首问/回链说明「使用种子回退，建议 init 落盘」）
3. 两者都没有 → 硬闸：先完成 `init`

`init` 会先扫描当前环境能调起的 skill，按 11 类能力归位，然后**停下来问你**。首问四选一：

| 选项 | 含义 | 后续 |
|---|---|---|
| **采用推荐包** | 全量套用 `config/stage-bindings.example.yaml` | 未安装项进入安装确认 |
| **采用 minimal** | 套用 `config/stage-bindings.minimal.yaml` | 关键环可能为 `null` → `start` 会**强制** `controller_proxy` 并告警 |
| **逐环调整** | 11 环逐个问（带中文名、候选、产物一句话） | — |
| **全部自行指定** | 逐环问，**无默认预填** | — |

**两个包的实际差异**

| 环节 | 中文名 | 推荐包 | minimal |
|---|---|---|---|
| `grill` | 澄清 | `grill-me` | `null` |
| `design` | 设计 | `brainstorming` | `brainstorming` |
| `domain` | 定稿 | `domain-modeling` | `null` |
| `spec` | 规格 | `brainstorming` | `brainstorming` |
| `plan` | 计划 | `writing-plans` | `writing-plans` |
| `proto` | 原型 | `prototype` | `null` |
| `testdesign` | 测试设计 | `lynxce-test-cases` | `null` |
| `implement` | 实现 | `subagent-driven-development` | `executing-plans` |
| `review` | 评审 | `code-review` | `null` |
| `verify` | 验证 | `qa` | `null` |
| `diagnose` | 排障 | `systematic-debugging` | `systematic-debugging` |

同屏还会问四个 `defaults`（跳过就写默认值）：

| 字段 | 取值 | 默认 |
|---|---|---|
| `defaults.invoke` | `strict` / `inline` | `strict` |
| `defaults.commit_policy` | `user_authorized` / `follow_plan` | `user_authorized` |
| `defaults.handoff_policy` | `auto` / `confirm` | `confirm` |
| `defaults.review_policy` | `subagent` / `inline` | `subagent` |

minimal 的 `defaults` 更保守：`invoke: inline`、`review_policy: inline`。

**写盘与禁止项**

- 唯一写入目标：`<目标仓>/docs/runs/stage-bindings.yaml`（无 `docs/runs/` 先建目录）。
- 未完成首问不写盘；首问**未展示含中文名的推荐包表**，不算完成首问。
- 安装缺失 skill 必须你同意，禁止静默安装。
- **禁止**代跑目标仓 `scripts/agent-config/sync.mjs`——绑定与工程化 sync 无关。
- 幂等：已有绑定文件时，先展示现状 + 推荐包对照，再问「保持现状 / 重置为推荐包 / 逐环改」。

### 2.4 rebind — 改环节 ↔ skill 映射

只改绑定，不跑流程、不动任何 `progress.yaml`。四种改法：全量重选 / 单环修改 / 重置为推荐包 / 只改 defaults。

改完的影响面（很重要）：

- 不影响**进行中主题的已有进度**，但**从下一环起**按新绑定调起。
- 改 `defaults.invoke` **不会**自动改已有主题的 `progress.invoke`——进行中主题仍以 `progress` 为准。
- 当前环还没调起子 skill 时，换绑立即生效；已调起并完成的环不追溯。

## 3. 如何使用（主流程）

不必背模式 ID，直接说人话。

### 3.1 日常话术表

| 你说 | 触发 | 结果 |
|---|---|---|
| 「初始化绑定」/「首次接入」 | `init` | 写 `docs/runs/stage-bindings.yaml` |
| 「改绑」/「把 grill 换成 xx」 | `rebind` | 改绑定文件 |
| 「开工」/「新需求」/「跑一个 feature」 | `start` | 分诊 + 建主题目录 |
| 「继续」/「接着上次」 | `resume` | 续跑进行中主题 |
| 「看看进度」/「卡在哪」 | `status` | 只读播报，不写盘 |
| 「环 N 完成」/「本环完成」 | `advance` | L1 → L2 → 写盘 → 进下一环 |
| 「本环返工：…」 | `advance` 分支 | **不推进**，回当前环厨师 |
| 「暂停」 | `advance` 分支 | 建议写 `交接.md`，stage 不变 |
| 「收口」/「交付」/「归档」 | `close` | 双归档 + pitfalls 三问 |

模糊口令（比如「差不多了」）控制器会先复述「我按 advance 环 `<当前 stage>` 理解，对吗？」，确认后才写盘。

### 3.2 start — 新主题开工

顺序：**预检 → 分诊 → 定 slug → 仪式选项 → 建过程态 → 进第一环**。

**① 分诊（S / B / F）**

控制器读需求与仓库现状，**提议**一条路径并给依据（改动面大小、是不是新子系统、是否改公共接口、是否需要 ADR），**你确认**后才继续。未确认不得创建 `runs/` 下游产物。

**② slug**：`YYYY-MM-DD-<主题短名>`（中文可以，和 superpowers 文件命名一致）。

**③ 仪式四字段**

| 字段 | 可选值 | 默认 / 推导 |
|---|---|---|
| `run_mode` | `guided` / `express` / `unattended` | `guided` |
| `invoke` | `strict` / `inline` | `strict`（缺省跟 `defaults.invoke`） |
| `handoff_policy` | `auto` / `confirm` | `express`/`unattended` → `auto`；`guided` → `confirm` |
| `review_policy` | `subagent` / `inline` | `subagent` |
| `close_pitfalls` | `off` / `optional` / `on` | 有 `scripts/agent-kb/lint-pitfalls.mjs` → `on`；否则跟 `defaults`（缺省 `optional`） |

`unattended` 会做**一次性集中降级**（必须落盘备注）：`invoke` → `inline`、`review_policy` → `inline`、`handoff_policy` → `auto`；硬闸 `authorized_by` 只能写真实 `user_task_<id>` 或 `policy_exception`，**禁止**伪造 `user_chat` 笔录。

**④ 三项宿主探测式降级（禁止静默）**

| 情况 | 动作 | 必须留痕 |
|---|---|---|
| 宿主无 Task / 子代理能力 | `review_policy: subagent → inline` | 回链 + 门禁备注写原因 |
| 有 Task 但实际用同会话审核帽（含 CloudAgent/executor） | 降 `inline` 或记 `review_effective: inline` | 回链写「同会话审核帽」 |
| 宿主无 Task，或当前是 CloudAgent / executor / 单会话编排 | `invoke: strict → inline` | `progress.invoke: inline` + 回链写原因 |

**⑤ 写盘产物**

```text
docs/runs/active/<slug>/
  progress.yaml     # 机读 SSOT，schema: topic-run/1
  回链.md            # 产物指针总表，仅控制器维护
docs/runs/README.md  # 可选，过程态导航
docs/superpowers/README.md  # 仅 F 或你要求时，登记进行中主题行
```

### 3.3 advance — 环末推进

```text
厨师结束 → 回报产物路径
  → L1（形状勾选，只读当前 stage 那节）
  → L2（语义审核，subagent 优先）
  → 硬闸短确认（若需要）
  → 写 progress.yaml / 回链.md / gates
  → 按 handoff_policy 主动调起下一环
```

- **L1 不过 → 停**，不跑 L2，stage 不变。
- **L2 `result: fail` → 停**，列缺陷，回厨师返工。
- 环数 ≥ 5 或上下文过长 → 控制器会提议先写 `交接.md`。
- `handoff_policy=confirm` 时，进下一环前会给短卡片；你说「不」→ 记 `pending_invoke`，下次 `resume` 再调起。

### 3.4 resume / status

**resume**（续跑主题，五步）：列 `docs/runs/active/` 下主题 → 读 `progress.yaml` → 有 `交接.md` 先读它 → 播报当前环与产物 → 按 stage 继续（桥/闸/需 skill 分别处理）。

以下情况控制器会建议**先写交接、换新会话再续**：你表示接不上上下文、没有 `交接.md` 且 `updated_at` 距今 ≥ 7 天、你否认播报准确性、或已完成 ≥ 5 环。

**status**（只读）：进行中主题列表（`stage=done` 未归档的会标 `needs-close`）→ 绑定健康表（`null` 标红，建议 rebind/init）→ 指定主题明细（字段、产物存在性 ✓/✗、审核结论、未过闸）→ 建议下一步。

看到 `null` 绑定**不要**在 status 里改，改绑走 `rebind`。

### 3.5 close — 收口

前置：F 需 `测试报告.md` 无 `fail`（或你在 `accepted_residual` 显式接受残留）；B 需 Gate 已过（冒烟为建议项）；S 只记结论，不走 superpowers 归档。

收口动作：

1. **仓库收口清单优先**：若目标仓有 `docs/agent-kb/delivery-checklist.md`，以它为准逐项勾选，本手册只做兜底。
2. **契约同步**：仓里有 `docs/func|api|db|redis|jobs` 就逐项确认本主题变更已同步；没有就记「本仓无契约文档树」并跳过，不阻断。实现在 PR 分支、本地没有业务文件时，以远程 diff 可指认为准，回链记 `契约同步: pr_branch`。
3. **工程化快照（可选）**：`scripts/agent-kb/refresh-score.mjs` 或工程化 `harness.mjs --mode refresh`；结果三态——exit 0 → `eng_snapshot: refreshed`；exit 2 且你接受残留 → `stale` + blockers；exit 1 或命令不可用 → `stale`（不阻断）。
4. **双归档**：`docs/runs/active/<slug>` → `docs/runs/archive/<slug>`；Spec/Plan 徽章改「已交付」并移入 `docs/superpowers/archive/specs|plans/`，`ARCHIVE.md` 按日期倒序追加。
5. **死链改写**：归档后把主题内仍指向 `docs/runs/active/<slug>/` 的路径字符串改成 archive 路径（只改路径，不动语义）。
6. **pitfalls 三问**：本轮有没有修/确认智能体易再犯的错误做法？已有 Pn 落点还准吗？要不要新增条目？`close_pitfalls` 的 `off/optional/on` 决定是否跑 lint 脚本，`on` 时无脚本或失败会**阻断 close**。
7. **输出交付摘要**：产物路径、测试通过率、残留风险、跳过的可选增强、`eng_snapshot` 状态；`controller_proxy` 时摘要须注明「本主题 L2 为控制器自审」。

## 4. 11 环与三条路径

### 4.1 可绑环节（键名固定）

| # | 中文名 | 键名 | 主要产物 | 进入条件 | 推荐 skill |
|---|---|---|---|---|---|
| 1 | 澄清 | `grill` | 共享理解 + 可选术语/ADR 草稿 | S 轻 / B 按需 / F 必 | `grill-me` |
| 2 | 设计 | `design` | 设计确认摘要（或 `设计笔记.md`） | S 探查计划 / B 短设计 / F 完整 | `brainstorming`（须截断） |
| 3 | 定稿 | `domain` | ADR + `术语增量.md` | **仅** `domain=entered` | `domain-modeling` |
| 4 | 规格 | `spec` | Spec 设计文档 | **仅 F** | `brainstorming`（须截断） |
| 5 | 计划 | `plan` | 实施计划 / checklist | F 必 / B 可选 | `writing-plans` |
| 6 | 原型 | `proto` | 原型 + 交互说明 + 你的确认 | **仅** `proto=entered` | `prototype` |
| 7 | 测试设计 | `testdesign` | `测试用例.md` | **仅 F** | `lynxce-test-cases` |
| 8 | 实现 | `implement` | 业务代码 + 单测 | B/F（S 仅 throwaway） | `subagent-driven-development` |
| 9 | 评审 | `review` | 语义轨评审结论 | B/F | `code-review` |
| 10 | 验证 | `verify` | `测试报告.md` | **仅 F** | `qa` |
| 10b | 排障 | `diagnose` | 复现笔记 | 按需 | `systematic-debugging` |

注意两个命名坑：环 9 行名是「评审」、键名 `review`，但对应闸键是 **`gates.gate`**；`design` 与 `spec` 推荐**同绑** `brainstorming`，靠截断契约区分，指针卡片必须粘贴该环 `forbid:` 原文列表。

### 4.2 控制器自有环节（不绑子 skill）

`triage` · `domain-bridge` · `proto-bridge` · `go` · `pre-impl` · `handoff` · `advance` · `close`

另外 `stage` 还有几个旁态：`smoke`（冒烟，B 建议不强制）、`diagnose`（排障）。

### 4.3 三条路径

| 路径 | 适用 | 文档厚度 |
|---|---|---|
| **S Spike** | 可行性探查；结论就是答案，不入库代码 | 无 spec/plan，可选 throwaway 笔记 |
| **B Bounded** | 仓库已有可改流程的小变更 | 聊天短设计，可无独立 Spec |
| **F Full** | 新子系统 / 改公共接口 / 需 ADR 的决策 | 条件 ADR + Spec + Plan + 集成用例 + 测试报告 + 收口 |

**路径裁剪矩阵**

| 环节 | S | B | F |
|---|---|---|---|
| 0–2 分诊/澄清/设计 | 轻/按需 | 轻/按需 | ✓ |
| 2→3 定稿桥 | 按需 | 按需 | ✓（默认常 skipped） |
| 3 Domain | 仅 entered | 仅 entered | 仅 entered |
| 4 Spec | ✗ | ✗ | ✓ |
| 5 Plan | ✗ | 可选 | ✓ |
| 5→6 Proto 桥 | ✗ | ✓ | ✓ |
| 6 Proto | ✗ | 仅 entered | 仅 entered |
| 7 TestDesign | ✗ | **永不进入** | **必进** |
| 8 实现 | throwaway | ✓ | ✓ |
| 9 Gate | ✗ | ✓ | ✓ |
| 10 Verify | ✗ | **永不进入** | **必进** |
| 10′ 冒烟 | ✗ | 建议 | 可并入 10 |
| 11 收口 | 记结论 | 精简 | ✓ |

两条推导规则：

- **F 默认链路**：设计确认 → 定稿桥（多数 `skipped`）→ Spec。
- **B 没有独立 plan 文件时**：短设计确认后走「Go 等价三问」→ 写 `gates.go` → **立即**进 Proto 桥，不许空等「环 5 结束」。

### 4.4 express 的边界

`run_mode=express` 只压缩**确认节奏**，不压缩流程：

| 不跳过 | 可压缩 | 仍分环 |
|---|---|---|
| 分诊确认、计划 Go 闸、Pre-Impl、Verify（F）、Close | 澄清 + 设计同轮；共享理解闸 + 设计确认闸可用**一次总 yes**（两闸可写相同 ISO） | Spec 与 Plan 仍分环；设计后仍跑定稿桥；Proto 桥规则不变 |

`express` 下把 Pre-Impl「并进」首个实现提交 = 跳过独立闸，属于红旗。

## 5. 环间审核与闸门证据

### 5.1 L1 与 L2

| 层 | 查什么 | 谁做 | 产物 |
|---|---|---|---|
| **L1 形状** | 该环产物在不在、字段非空、链接可打开（只读当前 stage 那一节） | 控制器 | 无独立文件，结论写回 `progress` / `回链` |
| **L2 语义** | 产物内容够不够撑起「可以离开这一环」 | 审核员（子代理优先，否则同会话审核帽） | `审核-<stage>.md` |

L1 不过就不必跑 L2；L1 ∧ L2（适用时）都过才能写 `gates.*`。

### 5.2 审核文件

路径 `docs/runs/active/<slug>/审核-<stage>.md`，`<stage>` 用**英文键**（`审核-spec.md`、`审核-gate.md`）。固定骨架：

```markdown
# L2 review — <stage> — <slug>

- result: pass | fail
- reviewer: bound_subagent | inline_session | self(controller_proxy)
- summary: …
- defects:（fail 时逐条；pass 可空）
  - …
```

`result: fail` → 不推进；伪造 pass = 跳过硬闸，属红旗。

**闸 ↔ 审核文件映射**

| 闸键 | 必须的审核文件 |
|---|---|
| `shared_understanding` | `审核-grill.md` |
| `design_confirmed` | `审核-design.md` |
| `go` | `审核-plan.md` |
| `gate` | `审核-gate.md` |
| `verify` | `审核-verify.md` |
| `triage` / `proto_confirmed` / `pre_impl` / `close` | 无完整 L2 要求，但仍需合法授权 |

中途环也会被推断检查：`stage` 越过 `spec` / `testdesign`（仅 F）、`implement`、`domain`（仅 entered）时，须有对应审核文件且 `pass`。

### 5.3 硬闸清单

| 闸 | 时机 | 通过条件 |
|---|---|---|
| **绑定闸** | 每次调起子 skill 前 | 预检 A–E 全过：绑定文件有该键 / skill 非 null / 宿主可调起 / design·spec 已粘贴 `forbid` 原文 / implement 已问回退 |
| **分诊闸** | 环 0 | 控制器提议 S/B/F 并给依据，你显式确认其一 |
| **共享理解闸** | 环 1 末 | L1+L2 过 + 你确认可进设计 → `gates.shared_understanding` |
| **设计确认闸** | 环 2 末 | L1+L2 过 + 设计 yes → `gates.design_confirmed`，通过后跑定稿桥 |
| **定稿桥** | 环 2→3 | 必展示【定稿桥结论】块 → 写 `domain=skipped/skipped_by_user/entered`；「需要」时须你显式同意 |
| **计划 Go 闸** | 环 5 末 | L1+L2 过 + 三问成立（任务依赖无环 / 契约变更已列首批 / 每任务有可测验收）+ 你确认 → `gates.go` |
| **Proto 桥** | 环 5→6 | 必展示【Proto 桥结论】块 → 写 `proto=*`；本仓「需要」须你显式同意 |
| **Proto 确认闸** | 环 6 | 你显式确认 → ISO `gates.proto_confirmed`（`skipped*` 时保持 null） |
| **Pre-Impl 闸** | 环 7b | F：proto（若 entered）+ testdesign 两节 L1 全过、适用 L2 过、O8/O9/M3 满足；B：proto 勾选全过 |
| **Gate 闸** | 环 9 | L1 全过 + L2 过 + 机械轨 A–D 至少一项可指认 + 语义轨无未决 blocker |
| **Verify 闸** | 环 10（仅 F） | L1 全过 + L2 过 + `env_notes` 必要时含 `api_base_mode` / `pinned_deps` + `verify_commands` 每条 exit 0 |
| **Close 闸** | 环 11 | 收口步骤 + 双归档检查单；monorepo 时根 README 必须有双端启动命令 |

桥的结论块形如：

```text
【定稿桥结论】
- 需要独立定稿（ADR / 术语增量）：是 | 否
- 依据：…
- 建议：skipped | entered（待确认）
- 推翻方式：说「要进定稿」或「确认跳过定稿」
```

控制器自判「不需要」时**不许**强行问你「是否跳过」二选一；自判「需要」时**不许**静默 `entered`。两种都错了，可以推翻。

### 5.4 闸门证据条（本 skill 最硬的一条）

写任何 `gates.*` ISO 时间戳之前，三件事必须同时成立：

1. 回链「硬闸授权」表有对应行，`authorized_by` 合法；
2. 适用环的 `审核-<stage>.md` 已落盘且含 **`result: pass`**；
3. `chef_mode=controller_proxy` 时，回链「仪式与降级」节非空。

`controller_proxy` **不豁免**这条。机检：

```bash
node scripts/gate-evidence.mjs --cwd <仓根> --slug <slug>
# 等价：node scripts/feature.mjs gate-evidence --cwd <仓根> --slug <slug>
```

**合法 `authorized_by` 只有三种**

| 值 | 用在哪 |
|---|---|
| `user_chat` | 本会话你亲口确认（硬闸短卡片回复） |
| `user_task_<id>` | 任务级授权（批跑/无人值守），id 段至少含一位数字，如 `user_task_2026-09-21` |
| `policy_exception` | 策略例外，须在备注写明依据 |

**禁止**：伪造多轮「用户：确认」的假 transcript；自造 `user_task_fixture|auto|todo|placeholder|test|dummy`。

另外：`progress.proto=entered` 时必须有 ISO 的 `gates.proto_confirmed`；`gates:` 必须用 block style（写成内联 `{...}` 会被机检直接拒）。

### 5.5 红旗 — 见到就停

- 把「用户：确认」多轮假对话写入 `authorized_by`
- 自造 `user_task_fixture` / `user_task_auto` 等占位 task id
- 声称环完成但跳过 L2 / 不写 `审核-<stage>.md` / `result: fail` 仍写推进闸
- 把 `controller_proxy` 当作可跳过 advance / 硬闸的许可证
- `express` 下跳过 Pre-Impl，或把 Pre-Impl「并进」首个实现提交
- 只读 YAML `description` 或 SKILL 前几段就开干，不 Read `modes/`
- 「旧夹具说审核文件可不落盘」——已废除

**出现任一条：停写 gates，先补证据。**

### 5.6 常见借口对照

| 借口 | 现实 |
|---|---|
| 「赶时间，L2 以后补」 | 无 `审核-<stage>.md` + `result: pass` 不得写推进闸 |
| 「用户肯定会同意，先填确认」 | 假 transcript 非法；等真实短确认或真实 `user_task_<id>` |
| 「fixture/auto 先顶上」 | 占位 task id 非法 |
| 「proxy 模式我兼代厨师，闸也可以省」 | proxy 只改厨师帽，证据条与 `bound` 相同 |
| 「description 已经写了流程」 | description 只触发加载，流程以 `modes/` 为准 |
| 「express 就跳过 Pre-Impl」 | express 只压缩 grill+design 节奏 |
| 「inline 就可以一边写代码一边改 progress」 | inline 只改调起形态，progress/回链/gates 仍只由 advance 写 |
| 「B 路径 close 不用双归档」 | Bounded 仍须 active→archive |

## 6. 过程态文件与进度真相

### 6.1 目录

```text
docs/runs/
  README.md                 # 过程态导航（可选）
  active/<slug>/            # 进行中
  archive/<slug>/           # close 后移入
docs/superpowers/           # Spec/Plan 语料 + README/ARCHIVE（不变）
```

主题目录常见文件：`progress.yaml`（机读 SSOT）、`回链.md`、`设计笔记.md`、`术语增量.md`、`测试用例.md`、`测试报告.md`、`门禁清单.md`、`审核-<stage>.md`、`交接.md`。

**过程态 ≠ 契约 SSOT。** 契约真相在 `docs/api|db|redis|func|jobs` 与 `AGENTS.md`；`docs/runs/` 只记这次怎么做的。主题术语**禁止**写进仓库根 `CONTEXT.md`，用 `术语增量.md`。

### 6.2 progress.yaml 顶层字段

| 字段 | 取值 | 含义 |
|---|---|---|
| `schema` | `topic-run/1` | 可选；旧主题缺省仍合法 |
| `slug` / `title` / `created_at` / `updated_at` | 字符串 | 主题标识与时间 |
| `path` | `spike` / `bounded` / `full` | 分诊结果 |
| `run_mode` | `guided` / `express` / `unattended` | 仪式强度 |
| `invoke` | `strict` / `inline` | 子 skill 怎么调起 |
| `handoff_policy` | `auto` / `confirm` | 过闸后是否直接进下一环 |
| `review_policy` | `subagent` / `inline` | L2 谁来审 |
| `chef_mode` | `bound` / `controller_proxy` | 有没有厨师 |
| `stage` | 主链 + 旁态 | 当前环；`pre-impl` 用**连字符** |
| `domain` / `proto` | `skipped` / `skipped_by_user` / `entered` | 两座桥的结论 |
| `tasks` | `[{id,title,depends_on,status}]` | 计划任务，`pending/doing/done` |
| `env_verified` | `null` / `skipped` / `verified` | 实现期环境核验（可选） |
| `layout` | `monorepo` / `multi_repo` / `null` | 同仓布局 |
| `packages` | `[{path, role: api\|web\|other}]` | monorepo 包清单 |
| `docs_root` | 默认 `docs/` | 典礼文档根，别放子包 |
| `sibling_repos` | `[{url, role, spec_path}]` | 跨仓配对 |
| `accepted_residual` | 文本 | 你显式接受的残留 |

### 6.3 artifacts 与 gates

`artifacts.*`：

| 键 | 指向 |
|---|---|
| `adr` | `docs/adr/NNNN-*.md`（列表） |
| `spec` / `plan` | `docs/superpowers/specs|plans/...` |
| `proto` | 原型目录/文件，或降级后的 `设计笔记.md` |
| `context_delta` | 人读文件 **`术语增量.md`**（历史名 `context-delta.md` 已弃用） |
| `testcases` / `test_report` | `测试用例.md` / `测试报告.md`（仅 F） |
| `qa_report` | 外部 QA 报告（可选） |
| `implement` / `pr_url` | 实现说明 / PR 链接（可选） |

`gates.*` 九个，值是 **ISO 时间戳**，`null` = 未过：
`triage` · `shared_understanding` · `design_confirmed` · `go` · `proto_confirmed` · `pre_impl` · `gate` · `verify` · `close`

**命名别名坑**：`stage` 写 `pre-impl`（连字符），`gates` 写 `pre_impl`（下划线）。两者刻意不同，别手抖。

### 6.4 回链.md

产物指针总表，**只有控制器维护**，厨师只回报路径。九节：决策与术语 / 规划 / 原型 / 测试 / **仪式与降级** / **硬闸授权表** / 同仓布局 / 跨仓 / 其他。空指针写 `—`。

两节最关键：

- 「仪式与降级」——写 `chef_mode`、`invoke`（含降级原因）、`review_policy`（或 `review_effective`）、`eng_probe`、`close_pitfalls`。
- 「硬闸授权」——九行表，`闸 | 时间 | authorized_by | 备注`，是 `gate-evidence` 的核对依据。

### 6.5 env_notes

| 键 | 含义 |
|---|---|
| `runtime` | 实际运行版本（如 OpenJDK 21） |
| `target` | 声明目标（如 `engines.node`） |
| `mismatch_reason` | 差异原因 |
| `api_base_mode` | `proxy` / `absolute`（前端基址） |
| `pinned_deps` | `[{name, version, reason}]` |
| `verify_commands` | `string[]`，monorepo 双端命令 |
| `workdir_policy` | `repo_root`（默认，命令从仓根写） |

无差异、无前端基址、无钉依赖时可整体 `env_notes: null`。

## 7. 专项场景

### 7.1 没装厨师也能跑完 Full（`controller_proxy`）

关键环绑不上时，`start` 会**强制** `chef_mode: controller_proxy` 并红字告警——这是**显式降级**，不是默认。最小清单：

1. **绑定文件在**：目标仓 `docs/runs/stage-bindings.yaml`（或先 `init`）；F 的 `spec`/`plan`/`testdesign`/`implement`/`verify` 不能为 null，否则只能降级。
2. **过程态齐**：`progress.yaml` + `回链.md` 存在，回链「仪式与降级」写明 proxy。
3. **真实授权**：用 `user_chat` 或真实 `user_task_<id>`；批跑用 `run_mode: unattended` + `user_task_<id>`。
4. **环间照旧**：控制器戴厨师帽按 gates L1 落盘领域产物，但**仍走 advance**；无 Task 时 `review_policy` / `invoke` 显式降 `inline`。
5. **收口照旧**：双归档 L1 检查单一项不能少。

边界仍有效：proxy 不豁免证据条；能装厨师时优先 `bound`。

### 7.2 原型（Proto 桥）与轻量降级

自判依据：新页面/新路由、改布局或主交互流程、改前端组件呈现。若 Spec 写了菜单页面但本仓没有前端树 → 倾向 `skipped`，理由里必须写跨仓提示，禁止假装 UI 已覆盖。

绑不上原型 skill（`proto.skill` 为 null）或已 proxy 时，走官方降级：落盘 `设计笔记.md`，**必须**含交互草图（文字/ASCII 均可）+ 主路径 ≥3 步 + 关键状态枚举。**不要求**可点击 HTML；闸只认「草图 + 状态机」，但仍要你对草图点一次头。

### 7.3 同仓 monorepo（M1–M6 速记）

- **M1**：`layout: monorepo` + `packages: [{path, role: api|web|other}]` + `docs_root: "docs/"`；**禁止**用 `sibling_repos` 指向本仓包路径（伪跨仓）。
- **M2/M5**：`env_notes.verify_commands` 每条 exit 0 才写 `gates.verify`；`workdir_policy: repo_root`，命令从仓根写（`mvn -f backend test`、`npm --prefix frontend test`）。
- **M3**：单 Spec 强制三节 `## API` / `## UI` / `## 测试矩阵`。
- **M4**：根 README = 双端启动 SSOT；子包 README 只留短链。
- **M6**：合并旧仓时剥离子包 `docs/runs` 与 `docs/superpowers`；可选写 `docs/HISTORY-split-repos.md` 记旧仓指针。

### 7.4 跨仓配对（O8）与前端联调（O9）

- 提到「配对后端/前端」时，`progress.sibling_repos` 至少一条 `{url, role: api|web, spec_path}`；本仓 role=web 且声明了 api sibling → Spec 必须有「消费契约」小节或链接。
- Full + UI 时联调二选一：Vite `server.proxy['/api']`，或 Spring 的 `CorsConfigurationSource` Bean（只写 `cors(withDefaults())` 不算）。结论记 `integration_ready: cors_ready | proxy_ready | accepted_blocked`，在 Pre-Impl 与 Gate 两处检查。

### 7.5 环境与依赖（O11/O14）

- `pinned_deps` 记钉住的依赖与理由（如 `jsdom@^24`），避免「昨天能跑今天不能」。
- `api_base_mode: proxy | absolute` 决定前端基址形态，verify 时要能指认。
- 文档里的版本对照写真实输出（`node -v` 对 `engines`），别写「大概 18 以上」。

### 7.6 Gate 无 CI 时的可接受证据

| 序 | 可接受证据 |
|---|---|
| A | 本地 hooks / lint / smoke：命令 + exit 0 |
| B | `env_notes.verify_commands[]` 每条 exit 0 |
| C | PR Checks / CI 链接且结论可指认 |
| D | 无 CI：你接受本地自证 → `mech_track: local_self_attest` + 命令清单 |

**禁止**只写「测试已跑过」而没有命令 / 退出码 / 路径 / Checks。

## 8. 命令速查、FAQ 与文档索引

### 8.1 CLI

薄入口 `scripts/feature.mjs` **只做转发**：不写 progress、不调子 skill、不跑硬闸。

```bash
node scripts/feature.mjs modes                  # 列 7 个模式 + 4 本 specs 手册
node scripts/feature.mjs status   --cwd <仓根>   # 转发 status-scan
node scripts/feature.mjs status-scan --cwd <仓根>
node scripts/feature.mjs gate-evidence --cwd <仓根> --slug <slug>
node scripts/feature.mjs close-check   --cwd <仓根> --slug <slug>
```

| 脚本 | 作用 | 退出码 |
|---|---|---|
| `scripts/status-scan.mjs` | 扫 `docs/runs/active/`，列 slug/stage/path；`done` 未归档标 `needs-close` | 0（无 active 也友好退出） |
| `scripts/gate-evidence.mjs` | 核对回链授权行 + `审核-*.md` pass + proxy 仪式节 + proto 一致性；不写盘 | 0 pass / 1 fail / 2 参数缺失 |
| `scripts/close-check.mjs` | archive 存在、`stage=done`、`gates.close`、无死链、ARCHIVE Commit 列，并组合跑 gate-evidence | 同上 |
| `scripts/selfcheck.mjs` | 技能包自身烟测（静态断言 + 夹具行为） | 0 / 1 |

`--expect-fail` 用于夹具反向验证（期望失败时返回 0）。

### 8.2 FAQ

**Q1 点名了但没反应？**
确认技能在宿主可加载目录、**新开过会话**、并且显式说了「feature-eng」。它是 `disable-model-invocation: true`，不点名不会自动加载。

**Q2 Agent 一直出计划不写文件？**
没绑定时它真的写不了——先 `init`。有绑定时，检查是不是卡在首问/闸门等你回话。

**Q3 绑定文件 `docs/runs/stage-bindings.yaml` 丢了？**
重新 `init`。期间会回退到技能包 `config/stage-bindings.yaml` 种子，回链/首问里会提示「使用种子回退」。

**Q4 `resume` 到底是续什么？**
续**主题**（`docs/runs/active`）。工程化仓补缺口是另一件事，别混。

**Q5 为什么没跑 L2 就写了 gates？**
那就是 bug 或红旗，用 `gate-evidence` 一查就露。写闸前三件事：授权行、`result: pass`、proxy 时仪式节非空。

**Q6 `review_policy` 怎么自己变了？**
宿主没有 Task 能力、或实际用了同会话审核帽时会自动降 `inline`——**必须**在回链/门禁留痕，不静默就合规。

**Q7 夹具里的 `user_task_fixture` 能照抄吗？**
不能。占位 id 非法，机检直接失败。要么你亲口确认（`user_chat`），要么给真实任务 id。

**Q8 主题跑到一半能改路径吗？**
B→F 是**升级**：回 `start` 的分诊闸重新确认，`progress.path` 记变更。F→B 的静默降级**不允许**。

**Q9 monorepo 被当成跨仓了？**
同仓前后端用 `layout: monorepo` + `packages`；`sibling_repos` 只给真正的另一个仓。

**Q10 归档后还能改 Spec 吗？**
能改文件，但要同步 `ARCHIVE.md` 与 `progress.artifacts` 指针，别让 `close-check` 查出死链。

**Q11 版本以谁为准？**
`_meta/manifest.yaml` 的 `version`。文档抬头钉号与仓根 README 由 `sync-skill-version.mjs` 同步，`selfcheck` 会查漂移。

**Q12 只想看看现在什么情况，别动状态？**
说「看看进度」走 `status`。只读、不写盘。要动手再说「继续」。
