1. 这个技能是做什么的？

harness-eng 把「Agent Harness 工程化」做成可重复的施工仪式：探测仓库 → 推荐配置 → 你确认 → 再往目标仓写入去域化模板。

它落地的不是某业务系统的私有规范，而是一套跨仓可复用的协作骨架。

能力落在哪作用
协作入口根/分册 AGENTS.md、总览规则Agent 一进仓就知道命令、红线、文档优先级
契约骨架docs/func|api|db|redis|jobs + path-scoped rules「改代码前读真相、改后回写文档」有落点
知识回流docs/agent-kbpitfalls / 架构概览 / 已知缺口可沉淀
规划与软门禁docs/superpowers + hooks进行中事项可见；提交前软提醒（不拦截）
工具连接样例mcp.json.example 等教怎么接 MCP，真密不入库
多工具配置 SSOT（可选 L5）docs/agent-config/ + sync.mjs一份真相生成 Cursor / Claude / Qoder 等目录

解决了什么问题？

  1. 每个 AI 工具各写一套规则，Never do / 契约互相漂移，换工具就丢上下文。
  2. 文档和代码脱节：接口、库表、Redis Key 只在人脑里，Agent 只能猜。
  3. 「装了很多 markdown」≠「可以放心 AI 改业务」：空壳、TODO、未验收片段被当成真相。
  4. 大仓第一次工程化路径过长：探测、骨架、MCP、inventory、精填、验收、打分没有统一流水线。
一句话
技能负责「把仓库改造成适合多 AI 工具协作的工程形态」；业务真相仍由你们（或 Agent 按 Plan 精填）写进 docs/**，各工具只挂薄入口。

2. 如何安装和更新

技能本身装在 当前 Agent 宿主的用户级 skills 目录（保证 SKILL.md 在技能根目录）；施工产物写在 业务目标仓（装 skill ≠ 给业务仓落地 harness）。用户可能用 Cursor、Claude Code、Qoder、Trae、Codex 等，不要默认装到某一家的目录。

2.1 一句话安装（推荐）

对当前对话里的 Agent 说：

帮我把这个 skill 装到你当前 Agent 宿主的用户 skills 目录，地址：
https://github.com/18360732385/skills/tree/main/harness-eng
保证目录内直接有 SKILL.md，装完告诉我实际路径。

也可自己跑 CLI（全局；若提示复制/软链，优先 Copy）。--agent 按你用的宿主传，不要默认写成某一家：

npx skills add https://github.com/18360732385/skills/tree/main/harness-eng -g
# 需要指定宿主时加上：--agent <host>

装好后：新开 Agent 会话，再显式点名 harness-eng。

常见用户 skills 目录（示例，以宿主实际加载目录与官方文档为准）：

宿主用户 skills 目录示例
Cursor~/.cursor/skills/ 或 ~/.cursor/skills-cursor/
Claude Code~/.claude/skills/
Codex / Qoder / Trae / 其他按该宿主文档

上述 URL 指向 main；若要跟踪施工主干，可改成当前发布分支（如 V0.5.X）。

2.2 一句话更新

帮我更新本机的 harness-eng skill：从
https://github.com/18360732385/skills/tree/main/harness-eng
覆盖安装到你当前 Agent 宿主的用户 skills 目录（保留备份或直接覆盖均可），完成后核对 SKILL.md / manifest 版本。

或再次执行上面的 npx skills add ...（按宿主传 --agent），然后新开会话。目标仓 docs/harness-eng/harness-meta.yaml 的 skill_version 可随后续 resume / upgrade 对齐。

2.3 从本源仓使用（开发 / 自测）

若你就在含 harness-eng/ 的 skills 仓库里对话，直接点名技能即可。路径因宿主而异，常见为：

  • 仓库内：harness-eng/（本仓布局）
  • 或已拷到某宿主用户目录：<host-skills-dir>/harness-eng/

2.4 手动拷贝安装

把同一目录拷到 当前宿主的用户 skills 目录，保证 <host-skills-dir>/harness-eng/SKILL.md 直接存在：

# Windows PowerShell
Copy-Item -Recurse -Force <源>\harness-eng <host-skills-dir>\harness-eng

# macOS / Linux
cp -R <源>/harness-eng <host-skills-dir>/harness-eng

路径示例（非唯一）：Cursor 常见 ~/.cursor/skills/harness-eng（或 skills-cursor）；Claude Code 常见 ~/.claude/skills/harness-eng；其余按该宿主文档。

2.5 前置条件

  • 本机可用 Node.js（渲染、打分、验收、报告等脚本为 .mjs）。
  • 写盘前必须过 确认闸门；审计模式默认不写文件。
  • 多工作区 / 多模块仓要先确认 目标根目录，技能只写已确认的根。
  • 一句话安装装的是 skill 文件；要给业务仓施工，需另说「流水线 / 落地 / 审计」等。

3. 如何使用（自然语言即可）

不必背内部模式名。对 Agent 点名 harness-eng，再用场景话描述意图即可。

3.1 按场景怎么说

你想做什么可以这样说Agent 大致会走
大仓第一次全面工程化「用 harness-eng 跑流水线，目标 L4」audit → L4 骨架 → MCP 矩阵/闸 → 填充计划 → 多 Agent 精填 → 打分 / HTML 报告
只想看缺什么、先别改仓「审计一下本仓 harness 成熟度」对照 L0–L5，默认不写盘
从零或按阶梯装骨架「给这个仓落地 harness，做到 L2，域只要 api 和 db」探测 → 推荐包 → 提问 → WritePlan → 等你确认 → 渲染
已经装了一半「续跑补齐缺口，不要覆盖我已有的 Never do」读 meta，只补缺，on_exists=skip
升一阶「从现在完整阶升阶到 L3」按 upgrade 规格差分补齐
深填契约真相「按 fill-plan 做多 Agent 填充」过填充 MCP 闸 → 批次精填 → acceptance → merge → score
能不能开 AI 改业务「跑完整度打分 / 开干闸」看 ai_coding_ready，打开 docs/harness-eng/report-latest.html

不确定选项时，回复 「全部推荐」：按探测结果的推荐包收齐答案；写盘仍要再确认一次（或先说预授权）。

3.2 标准施工节奏

  1. 探测：指纹仓库类型（空仓 / 半成品 / 已成熟 / 已有 Claude 外源等）。
  2. 推荐包：给出 RecommendedProfile（阶梯、契约域、分册、AI 工具面等）。
  3. 提问：每批尽量 ≤5 题；可「全部推荐」。
  4. WritePlan：白话摘要 + 文件动作表 + 渲染预览。
  5. 确认闸门：你明确说确认类词语之后，才真正写盘。
  6. 自检与移交：对照阶梯清单；打印分级 TODO（密钥泄露、空壳补真相等）。

3.3 确认与预授权（写盘前必过）

确认闸门
在回复下列任一之前，Agent 不应往目标仓写 harness 文件： 确认 · 确认写入 · 按计划执行 · 执行 WritePlan · LGTM

也可子集确认，例如：只执行 L0、去掉 14 后执行。若首轮同意 预授权，同会话后续的 resume / fill 可自动写盘。

3.4 推荐最短路径（大仓）

  1. 「点名 harness-eng，跑流水线，目标 L4，填充用 agents，金标批次。」
  2. 「全部推荐 → 确认预授权 → 确认。」
  3. 骨架与 MCP 闸过完后，继续填充战役；验收合并后打开 docs/harness-eng/report-latest.html。
  4. 看报告上的 开干（ai_coding_ready） 与 金标达标率（gold_ratio）；启发式草稿只留在 .fill-work，不要当 SSOT。

3.5 本地脚本（可选）

在 harness-eng 技能目录执行（--root 指向业务目标仓）：

cd <harness-eng技能目录>
node scripts/fill-plan.mjs --root <目标仓> --init --gold --sample-n 30
node scripts/fill-score.mjs --root <目标仓>
node scripts/fill-report-html.mjs --root <目标仓> --score docs/harness-eng/score-latest.json
node scripts/acceptance-check.mjs --root <目标仓> --domain api
node scripts/selfcheck.mjs

5. 一个仓库如何同时支持多套 AI 工具？

核心原则
契约一份，入口多份，生成物可同步。

5.1 落地时多选 AI 工具面

在提问 Q_AI_TOOL 时勾选 Cursor + Claude + Qoder + Trae… 确认写入后，技能会：

  • 为每个已选工具生成对应适配文件；
  • 把 ai_tools 列表记入 docs/harness-eng/harness-meta.yaml；
  • 对不全量镜像的宿主写入 契约 sync 指针（Codex 始终；claude/qoder/trae/workbuddy 仅 L0–L2）；L3+ / L5 全量镜像宿主不再强制冗余 1x；
  • 不删除未选工具目录里你已有的用户文件（续跑时 skip）。

5.2 已有 Claude / 外源规则时（FOREIGN）

  • 保留 CLAUDE 并存：不动 Claude 文件，另装 AGENTS / rules / 契约；冲突裁决写进 AGENTS。
  • 逐步迁到 AGENTS：暂留 Claude，迁移完成后你再决定是否归档。
  • 只加契约与 agent-kb：不强装根 AGENTS / alwaysApply 规则。

删除 CLAUDE.md 必须你书面确认，技能默认不删。

5.3 多工具长期维护：升到 L5（推荐）

  • 单一真相：docs/agent-config/（rules / hooks / mcp / settings / skills）
  • 生成器：scripts/agent-config/sync.mjs；用 --check 查漂移
  • 生成物带 GENERATED 标记 → 勿手改；改 SSOT 再 sync

5.4 协作纪律

  1. 业务 Never do、接口/库表真相只改 AGENTS / docs/**。
  2. 各工具入口文件只保留「指向 SSOT」的薄指针。
  3. MCP 真密只放本机/本仓约定位置，example 可入库。
  4. 填充与打分以文件系统 + Node 脚本为准，与当前打开哪个 IDE 无关。

6. 如何确认「工程化完成程度」够支撑 AI Coding？

10 秒结论（首页标准）

你在仪表盘上看到是否可以宣称 AI Coding
决策台徽章 = 「建议可以开干」，且 KPI 可 AI coding = YES 可以（仍须人工审）
徽章 = 「建议暂缓」，或开干 = NO / 有 blockers 不可以
仅阶梯到了 L4，或「仪表参考分 / overall」很高 不可以（参考分 ≠开干）
金标达标率很高，但开干仍 NO 不可以（金标不替代开干闸）

L5 配置 SSOTagent-config + sync --check生成物勿手改、无漂移

大仓常见起步：一次到 L4，再填真相；多工具仓再考虑 L5。

6.5 开干仍须人工审

即使决策台为 「建议可以开干」，含义是「建议可以开始用 AI 改业务」，不是保证无错。启发式（quality: heuristic）片段不得冒充已晋升的 SSOT。

7. 常见问题（FAQ）

Q1：装了技能但对话里没反应？

确认技能目录在宿主可加载路径；重启或新开会话；话术里显式点名 harness-eng。MATURE 仓未点名时，默认倾向只做审计。

Q2：Agent 一直出计划不写文件？

这是设计如此。须回复确认闸门等价词。若希望同会话连续填充，首轮一并确认预授权。

Q3：会不会覆盖我手写的 AGENTS Never do？

续跑 / merge 策略下：同名章节正文保留，只追加缺失章节。FOREIGN 仓删除 Claude 文件必须你书面同意。

Q4：骨架装完就能让 AI 大规模改业务吗？

不能单凭阶梯。请看 ai_coding_ready。仅有空壳或未关 fill-plan 时，开干应为 NO。

Q5：db / redis 域为什么填不下去？

需过填充 MCP 闸：矩阵达标且（MCP 烟测或 live 校准）通过。未过闸应停留在骨架。

Q6：README 里好像有密钥，技能会自动删吗？

不会。只检测并列入移交 TODO，由人工处理。

Q7：多模块大仓 glob 怎么选？

大仓【推荐】focused（收窄到入口与确认模块）。分册可选 solo / few / all。

Q8：Cursor 和其他工具规则不一致怎么办？

先看对齐矩阵：Cursor / Claude / Qoder / WorkBuddy 高；Trae 中高；Codex 部分（P2），不要假定 Codex 已全量同步。短期：不全量镜像的宿主（尤其 Codex）检查契约 sync 指针；L3+ 看本宿主 *-sync*，不必强求 1x-contract-sync。权威是根 AGENTS.md + docs/**。长期升 L5，以 docs/agent-config/ 为 SSOT，用 sync.mjs --check 防漂移。

Q9：Qoder / Trae 为什么不用 Cursor 式 hooks？

走 Claude 族协议（settings.json 或 .trae/hooks.json + claude-adapter.js），有 hooks，只是事件名与 Cursor 不同。Claude 族含 claude / qoder / trae / workbuddy；L3 另有 .githooks 兜底。

Q10：打分 overall 很高但开干仍是 NO？

常见原因：fill-plan 未关、覆盖未达标、acceptance blocker、TODO、缺 inventory。以报告 blockers 为准。

Q11：heuristic 草稿能直接当正式契约吗？

不能。须过 acceptance-check 再 merge；启发式须标 quality: heuristic 并留在 .fill-work。

Q12：版本以谁为准？

技能版本看 templates/_meta/manifest.yaml（当前 0.6.0）与目标仓 skill_version。报告对照 skill_version + report_schema（JSON 仍暴露 ui.version 同值）。报告壳版本 ≠ skill。

Q13：只想审计、怕写错兄弟仓？

说「审计」；多根时先确认 Q_TARGET_ROOT。审计默认不写盘。

Q14：流水线和落地有什么区别？

落地 land：按目标阶梯安装/合并骨架。

流水线 pipeline：一次确认串联审计 → L4 骨架 → MCP 闸 → inventory → fill-plan → agents → score（大仓首次【推荐】）。

半成品用续跑；已成熟默认审计。
