## 1. 这个技能是做什么的？

**harness-eng** 把「Agent Harness 工程化」做成可重复的施工仪式：探测仓库 → 推荐配置 → 你确认 → 再往目标仓写入去域化模板。

它落地的不是某业务系统的私有规范，而是一套**跨仓可复用**的协作骨架。对外用**三档**理解（写盘/审计仍用内部 L0–L5，细阶见 [ladder.md](../modes/ladder.md)）：

| 对外三档 | 内部阶 | 落在哪 | 作用 |
|---|---|---|---|
| **协作入口** | L0 | 根/分册 `AGENTS.md`、总览规则、meta | Agent 一进仓就知道命令、红线、文档优先级 |
| **契约与回流** | L1–L2 | `docs/func\|api\|db\|redis\|jobs` + agent-kb | 契约有落点；pitfalls / 架构可沉淀 |
| **门禁·工具·SSOT** | L3–L5 | superpowers · hooks · MCP example · 可选 `agent-config`+sync | 软提醒、工具样例、多工具配置一处改 |

施工现场（评分、报告、填充进度）默认在目标仓的 `docs/harness-eng/`。

### 解决了什么问题？

1. **每个 AI 工具各写一套规则**，Never do / 契约互相漂移，换工具就丢上下文。  
2. **文档和代码脱节**：接口、库表、Redis Key 只在人脑里，Agent 只能猜。  
3. **「装了很多 markdown」≠「可以放心 AI 改业务」**：空壳、TODO、未验收片段被当成真相。  
4. **大仓第一次工程化路径过长**：骨架、MCP、inventory、精填、验收、打分没有统一流水线。

**一句话**：技能负责「把仓库改造成适合多 AI 工具协作的工程形态」；业务真相仍由你们（或 Agent 按 Plan 精填）写进 `docs/**`，各工具只挂薄入口。运营纪律含 **Pn 回流**（Never do↔pitfalls）与契约门禁；可选 OpenAPI→Apifox 桥。细节见 glossary / CHANGELOG。

## 2. 如何安装和更新

技能本身装在 **当前 Agent 宿主的用户级 skills 目录**（保证 `SKILL.md` 在技能根目录）；施工产物写在 **业务目标仓**（二者不要混淆：装 skill ≠ 给业务仓落地 harness）。用户可能用 Cursor、Claude Code、Qoder、Trae、Codex 等，**不要默认装到某一家的目录**。

### 2.1 一句话安装（推荐）

对当前对话里的 Agent 说：

```text
帮我把这个 skill 装到你当前 Agent 宿主的用户 skills 目录，地址：
https://github.com/18360732385/skills/tree/main/harness-eng
保证目录内直接有 SKILL.md，装完告诉我实际路径。
```

也可自己跑 CLI（全局；若提示复制/软链，优先 **Copy**）。`--agent` 按你用的宿主传，不要默认写成某一家：

```bash
npx skills add https://github.com/18360732385/skills/tree/main/harness-eng -g
# 需要指定宿主时加上：--agent <host>
```

装好后：**新开 Agent 会话**，再显式点名 **harness-eng**。

常见用户 skills 目录（示例，以宿主实际加载目录与官方文档为准）：

| 宿主 | 用户 skills 目录示例 |
|---|---|
| Cursor | `~/.cursor/skills/` 或 `~/.cursor/skills-cursor/` |
| Claude Code | `~/.claude/skills/` |
| Trae | `~/.trae/skills/` 或项目 `.trae/skills/`（示例 ≠ 唯一安装目标） |
| Codex / Qoder / 其他 | 按该宿主文档 |

生产装/升用上面的 **`main`**。

### 2.2 一句话更新

```text
帮我更新本机的 harness-eng skill：从
https://github.com/18360732385/skills/tree/main/harness-eng
覆盖安装到你当前 Agent 宿主的用户 skills 目录（保留备份或直接覆盖均可），完成后核对 SKILL.md / manifest 版本。
```

或再次执行上面的 `npx skills add ...`（按宿主传 `--agent`），然后新开会话。目标仓 `docs/harness-eng/harness-meta.yaml` 的 `skill_version` 可随后续 resume / upgrade 对齐。

### 2.3 从本源仓使用（开发 / 自测）

若你就在含 `harness-eng/` 的 skills 仓库里对话，直接点名技能即可。路径因宿主而异，常见为仓库内 `harness-eng/`，或已拷到 `<host-skills-dir>/harness-eng/`。

### 2.4 手动拷贝安装

把同一目录拷到 **当前宿主的用户 skills 目录**，保证 `<host-skills-dir>/harness-eng/SKILL.md` 直接存在：

```powershell
# Windows
Copy-Item -Recurse -Force <源>\harness-eng <host-skills-dir>\harness-eng
```

```bash
# macOS / Linux
cp -R <源>/harness-eng <host-skills-dir>/harness-eng
```

### 2.5 前置条件

- 本机可用 **Node.js**（渲染、打分、验收、报告等脚本为 `.mjs`）。  
- 写盘前必须过 **确认闸门**（见下文）；审计模式默认不写文件。  
- 多工作区 / 多模块仓要先确认 **目标根目录**，技能只写已确认的根。  
- 一句话安装装的是 **skill 文件**；要给业务仓施工，需另说「流水线 / 落地 / 审计」等。

## 3. 如何使用（自然语言即可）

不必背内部模式 ID。对 Agent **点名 harness-eng**，用**对外四支**说话即可（压缩表亦见 [SKILL.md](../SKILL.md) / [QUICKSTART.md](../QUICKSTART.md)）。

### 3.1 对外四支

| 支 | 对 Agent 说 | 结果 |
|---|---|---|
| **流水线** | **流水线** / pipeline | 大仓首次：audit → L4 骨架 → MCP 闸 → inventory → fill-plan → agents → score → HTML 报告 |
| **施工** | **落地** / **续跑** / **升阶** / seed-truths | 装或补骨架（半成品用续跑，`on_exists=skip`） |
| **审计 / 自证** | **审计** / **会话自证** | 对照 L0–L5 缺口或核验当前宿主；audit 默认不写盘 |
| **填充** | **填充** / fill-plan / agents / **打分** | MCP 过闸 → Plan → agents → acceptance → merge → score |

子意图挂在支上：升阶 / 补空壳 → 施工；session-live → 审计/自证；完整度打分 / 开干闸 → 填充。

不确定选项时，在提问批次里回复 **「全部推荐」**：按探测结果的推荐包收齐答案；**写盘仍要再确认一次**（或先说预授权）。

### 3.1.1 公开 CLI

自然语言点名即可；若脚本/Agent 直调 Node，只认统一入口：

| 用途 | 命令 |
|---|---|
| 写盘（land / resume / upgrade / pipeline-skeleton） | `node scripts/harness.mjs --root <TARGET> --params <params.json> [--mode …]` |
| inventory | `node scripts/fill-inventory.mjs --domain <api\|func\|db\|redis\|jobs> --root <TARGET>` |
| merge | `node scripts/fill-merge.mjs --domain <id> --inventory … --work-dir … --check\|--write` |

更多 fill CLI 见 [fill/README.md](../fill/README.md)。旧 shim 替换见 [upgrade.md](../modes/upgrade.md)。

### 3.2 标准施工节奏（施工 / 流水线）

1. **探测**：指纹仓库类型（空仓 / 半成品 / 已成熟 / 已有 Claude 外源等）。  
2. **推荐包**：给出 RecommendedProfile（阶梯、契约域、分册、AI 工具面等）。  
3. **提问**：每批尽量 ≤5 题；可「全部推荐」。  
4. **WritePlan**：白话摘要 + 文件动作表 + 渲染预览。  
5. **确认闸门**：你明确说确认类词语之后，才真正写盘。  
6. **自检与移交**：对照阶梯清单；打印分级 TODO。

### 3.3 确认与预授权（写盘前必过）

在下列**任一**回复之前，Agent **不应**往目标仓写 harness 文件：

- `确认` · `确认写入` · `按计划执行` · `执行 WritePlan` · `LGTM`

也可子集确认，例如：`只执行 L0`、`去掉 14 后执行`。

若首轮同意 **预授权**，同会话后续的 resume / fill 可自动写盘；否则每一轮填充仍要确认。词表以 [write-plan.md](../modes/write-plan.md) 为准。

### 3.4 推荐最短路径（大仓）

1. 「点名 harness-eng，跑流水线，目标 L4，填充用 agents，金标批次。」  
2. 「全部推荐 → 确认预授权 → 确认。」  
3. 骨架与 MCP 闸过完后，继续填充战役；验收合并后打开 `docs/harness-eng/report-latest.html`。  
4. 看报告上的 **开干（ai_coding_ready）** 与 **金标达标率（gold_ratio）**；启发式草稿只留在 `.fill-work`。

### 3.5 本地脚本（可选）

在 **harness-eng 技能目录**执行（`--root` 指向业务目标仓）：

```bash
cd <harness-eng技能目录>
node scripts/harness.mjs --root <目标仓> --params <params.json> --mode land
node scripts/fill-score.mjs --root <目标仓>
node scripts/fill-report-html.mjs --root <目标仓> --score docs/harness-eng/score-latest.json
node scripts/selfcheck.mjs
```

fill 家族（inventory / merge / plan）见 [fill/README.md](../fill/README.md)。Windows JSON 传参见 [write-plan.md](../modes/write-plan.md)。

## 4. 支持哪些 AI 编程工具？

真相与契约只维护 **一份 SSOT**：`AGENTS.md` + `docs/**`。  
各 AI 产品只生成 **入口适配**（短指针 / 薄规则），业务红线与 Pn **不**复制多份。权威矩阵：[ai-tools.md](../host/ai-tools.md)。

### 4.1 内置适配

| 工具 | 内部 ID | 典型生成入口 |
|---|---|---|
| **Cursor** | `cursor` | `.cursor/` rules / AGENTS |
| **Claude Code** | `claude` | `CLAUDE.md` + L3+ `.claude/rules` |
| **Codex** | `codex` | Starlark / hooks / toml / L5 skills（**高 · 纪律 B**；**不做** `.mdc` 镜像） |
| **Qoder** | `qoder` | `.qoder/rules` 镜像 |
| **Trae** | `trae` | `.trae/rules` + `.trae/mcp.json`（**高**） |
| **WorkBuddy / CodeBuddy** | `workbuddy` | 扁平 `.codebuddy/rules/*.md` + `/hooks` + 根 `.mcp.json` |

提问时 `Q_AI_TOOL` **可多选**。未探测到工具时，「全部推荐」的 `ai_tools` 为空，须追问；**不**默认 Cursor。Codex 仅探测到 `.codex/` 或显式勾选才纳入。

### 4.2 自定义工具

```text
自定义: 工具名=FooAgent; 入口路径=.foo/RULES.md
```

技能会在该路径写入指针模板。自定义工具**不会**自动装配宿主 hooks。

### 4.3 软门禁与 hooks / MCP 差异（L3+）

按**协议族**理解（详 [ai-tools.md](../host/ai-tools.md)）：

| 族 | 工具 | hooks（L3+） | MCP example（L4+） |
|---|---|---|---|
| **Cursor 族** | `cursor` | `.cursor/hooks.json` + 脚本 | `.cursor/mcp.json.example` |
| **Claude 族** | `claude` / `qoder` / `trae` / `workbuddy` | settings 或 `.trae/hooks.json` + adapter | 根或 `.trae` example |
| **Codex 族** | `codex` | `.codex/hooks.json` + adapter | 见 adapters/codex |
| **兜底** | 任意 L3+ | 建议 `core.hooksPath=.githooks` | — |

软门禁一律 **fail-open**。真密由 fill-mcp 写入；L4 只落 example。

### 4.4 0.5.2+ 多宿主对齐（摘要）

| 变更 | 说明 |
|---|---|
| **MCP 多路径** | `.cursor/mcp.json` ∥ 根 `.mcp.json` ∥ `.trae/mcp.json`（`mcp-paths.mjs`） |
| **Claude 全量 rules 镜像** | L3+ 镜像到 `.claude/rules/*.md` |
| **CodeBuddy** | 扁平 `.codebuddy/rules/*.md`；hooks **`/hooks`**；根 `.mcp.json`；见 [CODEBUDDY-PARITY.md](../host/CODEBUDDY-PARITY.md) |
| **适配卡** | [templates/ai-tools/adapters/](../templates/ai-tools/adapters/) |
| **L5 生成引擎** | [sync-hosts.md](../host/sync-hosts.md) + `scripts/agent-config/sync.mjs` |

### 4.5 对齐矩阵

| 工具 | 对齐程度 | 不要误读成 |
|---|---|---|
| Cursor / Claude / Qoder / WorkBuddy | **高** | — |
| Trae | **高** | 不是 Cursor 协议 |
| Codex | **高**（纪律 B） | 不做 `.mdc` 镜像；未探测不进「全部推荐」 |

权威是根 `AGENTS.md` + `docs/**`。L3+ / L5 全量镜像宿主不必再强求冗余 `1x-contract-sync`。

## 5. 一个仓库如何同时支持多套 AI 工具？

核心原则：**契约一份，入口多份，生成物可同步。**

### 5.1 落地时多选 AI 工具面

在 `Q_AI_TOOL` 多选后确认写入：为各工具生成适配；`ai_tools` 记入 meta；L0–L2 可写契约 sync 指针；L3+/L5 全量镜像与 Codex omit 冗余 `1x`；**不删**未选工具目录里你已有的用户文件。

### 5.2 已有 Claude / 外源规则时（FOREIGN）

走并存策略（`Q_COEXIST`）：保留 CLAUDE 并存 / 逐步迁到 AGENTS / 只加契约与 agent-kb。删除 `CLAUDE.md` 必须你书面确认。

### 5.3 多工具长期维护：升到 L5（推荐）

- 单一真相：`docs/agent-config/`  
- 生成器：`scripts/agent-config/sync.mjs`（`--check` 查漂移）  
- 生成物带 GENERATED 标记 → **勿手改**；改 SSOT 再 sync  

### 5.4 协作纪律

1. 业务 Never do、契约真相只改 `AGENTS` / `docs/**`。  
2. 各工具入口只保留指向 SSOT 的薄指针。  
3. MCP 真密：local 可填、勿提交；example 可入库。Agent **不**主动要求「别填密码」；仅在编辑 local 真密时提醒勿提交。  
4. 填充与打分以文件系统 + Node 为准，与当前打开哪家 IDE **无关**。

## 6. 如何确认「工程化完成程度」够支撑 AI Coding？

### 10 秒结论（首页标准）

| 你在仪表盘上看到 | 是否可以宣称 AI Coding |
|---|---|
| **决策台**徽章 = **「建议可以开干」**，且 KPI **可 AI coding / 开干 = YES**（`ai_coding_ready`） | **可以**（仍须人工审） |
| 徽章 = 「建议暂缓」，或开干 = NO / 有 blockers | **不可以** |
| 仅阶梯齐套、或「仪表参考分 / overall」很高 | **不可以**（参考分 **≠开干**） |
| **金标达标率**很高，但开干仍 NO | **不可以** |

权威页面：目标仓 `docs/harness-eng/report-latest.html`。

### 先分清两件事

| 概念 | 含义 | 够不够 AI 改业务？ |
|---|---|---|
| **阶梯齐套（脚手架）** | 三档/细阶文件在不在 | 只说明「脚手架在」；**不等于**可以开干 |
| **开干闸 `ai_coding_ready`** | 骨架 ∧ 覆盖 ∧ 语义 ∧ Plan 关闭 ∧ gate | **唯一**对外宣称「建议可以 AI 改业务」的闸 |

形态分 `overall`、贴顶信号等 **都不是**开干依据。

### 6.0 对话内会话仪表盘（工程轮末尾）

**里程碑 SHOW**：点名 **harness-eng** 且**本轮**有实质施工产出、闸门决策点（出示 WritePlan 或用户确认）、或显式要读数时，Agent 回复末尾附「## harness-eng 会话仪表盘」——决策 / 诊断 / 任务 / 趋势四台摘要，有 score 时再附一行纯文本施工态势（覆盖 × 形态；无 mermaid）；有宿主磁盘/live 数据时再附一行**宿主面**。提问批次 / RecommendedProfile / 定根前 / 等确认空轮 / 纯问版本号、安装、手册、术语、技能本身、改 skill、跑题则**整块省略**（即便同会话早先施工过）。含糊默认不附。规格 [session-dashboard.md](../modes/session-dashboard.md)。

| 元素 | 含义 |
|---|---|
| 四台表 | 会话内轻量快照；开干结论仍只看决策台 `ai_coding_ready` |
| 宿主面一行 | 磁盘齐套 / session-live 摘要；**磁盘 ≠ 生效**；不否决开干 |
| 施工态势 | 有 score 时一行纯文本；**无 mermaid** |
| **详情请查询仪表盘** | 链到目标仓 `docs/harness-eng/report-latest.html`（五台） |
| [使用手册.html `#s6`](使用手册.html#s6) · [使用手册.md · 第6章](使用手册.md#60-对话内会话仪表盘工程轮末尾) | **五台**完整读法 |

脚本：`node scripts/session-dash.mjs --root <目标仓> --intent engineering`。

### 6.1 怎么生成 / 打开 HTML 仪表盘

自然语言：「**完整度打分**」或「**开干闸**」。或：

```bash
node scripts/fill-score.mjs --root <目标仓> --focus full
# 【推荐】再出报告
node scripts/fill-report-html.mjs --root <目标仓> --score docs/harness-eng/score-latest.json
```

打开：`docs/harness-eng/report-latest.html`（`report_schema` **0.4.0**）。

### 6.2 仪表盘五台：看什么、到什么程度算 AI Coding

**能否 AI coding 只看决策台**；其余台解释「差在哪、下一步做什么、工具面是否自证」。

页顶**双轴进度**：

| 轴 | 含义 |
|---|---|
| **施工阶梯 L0–L5** | 脚手架位阶（来自 meta / ladder） |
| **开干闸路径** | skeleton → coverage → Plan → batches → semantic → ai_coding |

#### 决策台（唯一开干裁决）

| 界面元素 | 达到什么程度 | 含义 |
|---|---|---|
| **Verdict 徽章 / go_nogo** | **「建议可以开干」** | `ai_coding_ready=true` |
| | **「建议暂缓」** | 看 blockers + ≤3 条可复制命令 |
| **KPI：可 AI coding / 开干** | **YES** | 仪表盘「开干」**只看此项** |
| **KPI：金标达标率** | 越高越好 | **不替代开干** |
| blockers / 下一步 | 清空后重新打分 | 对齐 fill-plan / agents |

开干 YES 通常需：`skeleton_ready` ∧ `coverage_ready` ∧ `semantic_ready` ∧ Plan 全关 ∧ gate_profile 下 gate 通过。细则见 [fill-gate.md](../fill/fill-gate.md) / 当次 score JSON。

#### 诊断台 · 任务台 · 趋势台 · 宿主台

- **诊断**：覆盖/形态分域 + `diagnose.story`；贴顶但开干 NO → 关 Plan / 清语义 / gate，勿空追 overall。  
- **任务**：统一 `tasks[]`（shards / residual / 下一步命令）。  
- **趋势**：**仪表参考分 ≠开干**；旧 history（`report_schema < 0.4` 或 morph 不符）灰显、不连线。  
- **宿主台**：各 AI 工具 rules / hooks / MCP / githooks — **灰=磁盘存在，彩=session-live**；未自证显示空态；**不否决开干**。顶栏胶囊可一键切到本台。

### 6.3 对照表：仪表盘读数 → 行动

| 决策台状态 | 建议行动 |
|---|---|
| 建议可以开干 | 可 AI 改业务；合并前仍人工审 |
| 暂缓 · Plan 未关 | 继续 agents 关批次 |
| 暂缓 · coverage | 补 inventory + 分域真相 |
| 暂缓 · semantic | 按接口重填再 acceptance |
| 暂缓 · skeleton | resume / upgrade 到目标阶（常见 L4） |
| 暂缓 · gate | 清 gate 项；勿只追形态分 |

### 6.4 阶梯自检（脚手架维度）

| 对外三档 | 细阶 | 粗检 |
|---|---|---|
| 协作入口 | L0 | AGENTS / meta / 总览规则 |
| 契约与回流 | L1–L2 | 契约域 docs + agent-kb |
| 门禁·工具·SSOT | L3–L5 | hooks · MCP example · 可选 agent-config |

细阶 checklist：[ladder.md](../modes/ladder.md)。大仓常见起步一次到 **L4**，再填真相；多工具再考虑 L5。

### 6.5 开干仍须人工审

即使决策台为 **「建议可以开干」**，仍须审契约与代码；`quality: heuristic` 不得冒充已晋升 SSOT。

## 7. 常见问题（FAQ）

### Q1：装了技能但对话里没反应？

确认技能目录在宿主可加载路径；新开会话；**显式点名 harness-eng**（或四支话术）。MATURE 仓未点名时默认倾向审计。

### Q2：Agent 一直出计划不写文件？

须回复确认闸门等价词。同会话连续填充可首轮 **确认预授权**。

### Q3：会不会覆盖我手写的 AGENTS Never do？

merge：**同名章节正文保留**，只追加缺失章节。FOREIGN 删 Claude 须书面同意。

### Q4：骨架装完就能让 AI 大规模改业务吗？

不能单凭阶梯。看 **`ai_coding_ready`**。

### Q5：db / redis 域为什么填不下去？

须过 **填充 MCP 闸**（细则 [fill-mcp.md](../fill/fill-mcp.md)）：**过闸后再** inventory / agents；未过则停留骨架。

### Q6：README 里好像有密钥，技能会自动删吗？

不会。只检测并移交人工。

### Q7：多模块大仓 glob 怎么选？

大仓【推荐】**focused**。

### Q8：Cursor 和其他工具规则不一致怎么办？

看对齐矩阵（§4.5）。权威 `AGENTS.md` + `docs/**`。长期升 **L5** + `sync --check`。

### Q9：Qoder / Trae 为什么不用 Cursor 式 hooks？

它们走 **Claude 族**协议，有 hooks、事件名不同。勿把 Qoder 写成 Cursor `beforeShellExecution`。

### Q10：打分 overall 很高但开干仍是 NO？

以报告 **blockers** 为准，不是堆空文档。

### Q11：heuristic 草稿能直接当正式契约吗？

不能。须 acceptance 再 merge；启发式留 `.fill-work`。

### Q12：版本以谁为准？

技能版本看 `templates/_meta/manifest.yaml` 的 `version`（当前文档按 **0.7.14**）与目标仓 `skill_version`。报告对照 **`skill_version` + `report_schema`**（**报告壳 ≠ skill**）。

### Q13：只想审计、怕写错兄弟仓？

说「审计」；多根先确认目标根。审计默认不写盘。

### Q14：四支里流水线和施工有什么区别？

- **施工**（落地 / 续跑 / 升阶）：按目标阶装或补骨架。  
- **流水线**：一次确认串联审计 → L4 骨架 → MCP 闸 → 填充战役 → score（大仓首次【推荐】）。  
半成品用 **续跑**；已成熟默认 **审计**。
