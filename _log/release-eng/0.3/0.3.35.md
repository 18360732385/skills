# release-eng 0.3.35

日期：2026-11-23（Asia/Shanghai）

## 要点

- **修复：`db/migration` 下中文名 SQL 在整理时整体漏检**。git 默认 `core.quotepath=true`，`git ls-tree --name-only` / `git diff --name-only` 会把非 ASCII 路径输出为带引号的八进制转义（如 `"…/V261106100154556_1__chenpeng5__\345\215\261…sql"`）；`isMigrationSql` 的 `.sql$` 与路径比对因此全部不命中，新轨中文名（`V{ts}_{0|1}__{作者}__{中文描述}.sql`）既不进 candidates / `draft.sql`，也不会被拷进 `sql/refs/`、不会出现在整理文件与 `sql/README.md` 统计中。
- `release-freeze.mjs` 新增 `gitPaths()`：路径列举一律追加 `-z`，按 NUL 切分取原始 UTF-8 路径，不做 trim；`git ls-tree`（首次发版 / `listMigrationsOnRef` 基线）与 `git diff --name-only`（增量）全部改走该函数。
- `release-format.mjs` 新增 `extractMigrationNames(text)`：统一从发版单文本抽取 migration 名，支持旧轨 `Vdddd__…`、新轨 `V{ts}_{0|1}__…` 及中文描述；`release-freeze-enrich.mjs`（prior md 启发式）与 `release-seal-check.mjs`（Markdown ↔ artifacts 对账）改用同一函数，避免两处正则分叉。
- `selfcheck.mjs`：新增 035 断言——`isMigrationSql` / `classifyMigrationKindByFilename` / 发版单抽取对中文新轨名；并用临时 git 仓验证首次发版（`ls-tree`）与增量（`diff --name-only`）都能发现中文名 migration 并进入 `draft.sql`。
