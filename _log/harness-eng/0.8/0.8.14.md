# 0.8.14 — 实战总析仍待完善项收口（路径绑定 / 安装告警 / dry-run / type_export 文案）

日期：2026-11-27

## 本版

来源：harness-eng 0.8.13 升级 sms-ai 实战总析的「仍待完善」。逐项判定后只修技能自身缺陷；计分口径与 gold 门槛数值不动。把「审计 `evidence_path` 与库存路径错位从假 pass 改为不 pass」是门禁收紧，不是改门槛分数。

- **取消预授权文案**：`harness.mjs` Usage 与 `modes/write-plan.md` 对齐为写成 `preauth: false`、不删除已跟踪文件；不再写「清除该文件」
- **audit 路径绑定**：`validateAudit` 在传入库存期望路径时，核对 `evidence_path` 与当前资产路径；错位记 `kind: evidence`，不得计 pass。后缀连环平移（同一旧 id 指向另一文件）不再假绿
- **官方对账**：新增 `scripts/reconcile-audit.mjs`（`reconcileAudit`），按 `evidence_path` 把审计行的 `unit_id` 迁到当前库存 id。默认 dry-run，`--write` 才落盘；不改哈希与 verdict，不编造新行。refresh 只提示该工具，不自动搬移
- **安装副本告警**：文案按当前 mode 写（refresh 不再套用「upgrade 以正在执行的这份为准」）。默认扫描根追加 skills-manager-data 惯例路径与 `SKILLS_MANAGER_DATA` / `SKILLS_MANAGER_ROOT`；upgrade / refresh（含 dry-run）稳定打印。用夹具锁定，不依赖本机安装目录偶发输出
- **refresh `--dry-run`**：跳过 inventory/打分时标明「未计分 / dry-run 未跑门禁」；若磁盘已有 `score-latest.json`，回读 `ai_coding_ready` 并注明来源，不再用「覆盖/语义未就绪」覆盖已绿的 ready
- **type_export 索引片段**：`templates/docs/client-api/type-export-note.snippet` 可单独合并。厚仓 `on_exists=skip` 时，upgrade 真写只追加缺失说明，不整文覆盖已有 `client-api.md`；dry-run 与 refresh 在缺失时提示

- 覆盖=点名、audit 不读正文：文档化的真实性边界
- `type_export` 不计分：既定口径，本版只补索引说明
- rule 17 与 101 并存：只告警 + 确认后的 `git mv`，不静默改名、不自动删
- gitignore 追加机制：仍不自动删除目标仓里已取消的旧行
