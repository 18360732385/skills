# 0.8.0 — 仓型三分 · 前端五域 · rules 101 族

日期：2026-11-24  
来源：grilling 共识（18+3 问）——前端项目资产对标后端 `api|func|db|redis|jobs` 五域仪式（inventory → fill-plan → agents → merge → score）；参考 sms-ai-web 形态、语言中立化。

## 本版

- **仓型三分**：`harness-meta` 新增 `repo_kind`（frontend|backend|fullstack）+ `monorepo`；判定 = README/AGENTS + 代码成分启发式，不确定时提问 `Q_REPO_KIND`
- **前端五域**：`design` / `prototype` / `pages` / `components` / `client-api` 入 `domains.yaml`；0.8.0 起 **design·prototype 全链路计分**（inventory 扫描器 + merge 分支 + coverage），其余三域先落索引壳（0.8.1+ 精填升严）
- **rules 101 族**：`17-frontend-web(.full)` → `101-frontend-web(.full)`；`102-design-system` / `103-prototype` / `104-components` / `105-pages` / `106-client-api` 随域包下发；upgrade 退役旧 17 防双规则
- **归档纪律**：非运行文件（DESIGN*.md、原型 HTML）经确认归档仓根 `docs/<domain>/`；运行代码（tokens.css 等）留原地仅索引
- **评分**：`frontend_coverage` 由恒 `not_measured` 改按 design/prototype 实计；`repo_kind=frontend` 时开干覆盖只盯前端域
- 语言中立：探测不绑定 React/pnpm/antd（sms-ai-web 仅作形态参考）
